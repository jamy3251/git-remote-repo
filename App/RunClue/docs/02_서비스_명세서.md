## 1. 핵심 용어 정의

| 용어 | 영문 | 정의 |
|------|------|------|
| **클루 (Clue)** | Clue | 사용자가 생성하는 게임/이벤트/미션의 최상위 단위. 하나 이상의 Step으로 구성되며, 참여 조건·보상·검증 방식 등을 포함한다. |
| **스텝 (Step)** | Step | Clue를 구성하는 개별 미션 단계. 각 Step은 고유한 타입(CHECKPOINT, SNAPSHOT 등)을 가지며, 참여자가 순차 또는 비순차로 수행한다. |
| **증거 (Evidence)** | Evidence | 참여자가 Step 완료를 입증하기 위해 제출하는 데이터. 사진, 위치 좌표, 동영상, QR 스캔 결과, 텍스트 답변 등 다양한 형태를 포함한다. |
| **검증 (Validation)** | Validation | 제출된 Evidence가 Step 완료 조건을 충족하는지 판정하는 절차. 자동(auto), 지연(delayed), 수동(manual) 세 가지 방식이 존재한다. |
| **보상 (Reward)** | Reward | Clue 또는 Step 완료 시 참여자에게 지급되는 인센티브. 포인트, 뱃지, 쿠폰, 경품, 추첨권 등의 유형이 있다. |
| **생성자 (Creator)** | Creator | Clue를 기획·생성·관리하는 사용자 역할. Step 설정, 증거 검토, 보상 관리 권한을 보유한다. |
| **참여자 (Participant)** | Participant | Clue에 참여하여 Step을 수행하고 Evidence를 제출하는 사용자 역할. |
| **관리자 (Admin)** | Admin | 플랫폼 전반을 운영·관리하는 역할. Clue 승인, 신고 처리, 시스템 설정 등의 권한을 보유한다. |
| **시스템 (System)** | System | 자동 검증, 배치 처리, 알림 발송 등을 수행하는 서버 측 주체. |
| **클랜 (Clan)** | Clan | 참여자들이 팀을 구성하여 Clue에 참여하는 그룹 단위. Clue 설정에 따라 개인 또는 클랜 단위 참여가 결정된다. |
| **뱃지 (Badge)** | Badge | 특정 조건 달성 시 사용자 프로필에 부여되는 시각적 성과 표시. 누적형 또는 일회성으로 구분된다. |
| **신고 (Report)** | Report | 사용자가 부적절한 Clue, Evidence, 사용자, 댓글 등에 대해 제출하는 문제 보고. |
| **알림 (Notification)** | Notification | 시스템이 사용자에게 전달하는 이벤트 기반 메시지. 푸시 알림, 인앱 알림, 이메일 등의 채널을 통해 발송된다. |
| **포인트 (Point)** | Point | 플랫폼 내 통용되는 범용 보상 단위. Clue 완료, 출석, 이벤트 등을 통해 적립하며, 쿠폰 교환 등에 사용 가능하다. |
| **추첨권 (Raffle Ticket)** | Raffle Ticket | 경품 추첨에 참여할 수 있는 권한을 나타내는 보상 항목. |
| **쿠폰 (Coupon)** | Coupon | 제휴 업체 할인·무료 이용 등의 혜택이 담긴 디지털 쿠폰. |
| **경품 (Prize)** | Prize | Clue 완료 또는 추첨을 통해 지급되는 실물 또는 디지털 상품. |
| **자동 검증 (Auto Validation)** | Auto Validation | GPS 좌표 매칭, QR 코드 일치, 정답 비교 등을 시스템이 즉시 판정하는 검증 방식. |
| **지연 검증 (Delayed Validation)** | Delayed Validation | AI 이미지 분석, 텍스트 분석 등을 통해 비동기로 처리되는 검증 방식. 처리 시간이 소요된다. |
| **수동 검증 (Manual Validation)** | Manual Validation | Creator 또는 Admin이 직접 Evidence를 확인하고 승인/반려를 판정하는 검증 방식. |
| **피드 (Feed)** | Feed | 참여자들의 활동 기록, 완료 현황, Evidence 등이 표시되는 타임라인 영역. |
| **리더보드 (Leaderboard)** | Leaderboard | Clue 내 참여자 또는 클랜의 진행도·점수를 순위로 표시하는 기능. |

## 4. Step 타입별 명세

### 4.1 CHECKPOINT (위치 기반 체크포인트)

| 항목 | 내용 |
|------|------|
| **정의** | 참여자가 지정된 GPS 좌표 반경 내에 도달하면 완료로 인정되는 위치 기반 미션. |
| **입력 데이터 (Creator)** | 목표 위치 좌표(위도, 경도), 허용 반경(미터), 힌트 텍스트, 힌트 이미지(선택), 제한 시간(선택) |
| **제출 데이터 (Participant)** | 현재 GPS 좌표 (자동 수집), 타임스탬프 |
| **검증 방식** | **auto** - 참여자 GPS 좌표와 목표 좌표 간 거리가 허용 반경 이내인지 자동 판정 |
| **UI 요소** | 지도 뷰 (목표 위치 표시 여부는 Creator 설정), 현재 위치 표시, 거리 안내 (힌트 모드), 도착 확인 버튼, 제한 시간 타이머 |
| **제약 조건** | 허용 반경: 최소 10m ~ 최대 5,000m. GPS 정확도 ±15m 이내 필요. 실내 환경에서 GPS 정확도 저하 가능. |
| **실패 시나리오** | GPS 비활성화 → 위치 권한 요청 안내. GPS 정확도 부족 → 재시도 안내 (정확도 표시). 허용 반경 이탈 → "아직 목표 지점에 도착하지 않았습니다" 메시지. 제한 시간 초과 → Step 실패 처리 (재도전 가능 여부는 Clue 설정에 따름). 위치 조작(Mock GPS) 탐지 → Evidence 무효 처리 및 경고. |

### 4.2 SNAPSHOT (사진 증거)

| 항목 | 내용 |
|------|------|
| **정의** | 참여자가 지정된 주제 또는 대상의 사진을 촬영하여 제출하는 미션. |
| **입력 데이터 (Creator)** | 미션 설명 텍스트, 예시 이미지(선택), 필수 포함 요소 설명, 검증 방식 선택(auto/delayed/manual), AI 검증 키워드(delayed 선택 시), 최소/최대 사진 수 |
| **제출 데이터 (Participant)** | 촬영 사진 (1장 이상), EXIF 메타데이터 (촬영 시각, GPS), 선택적 텍스트 설명 |
| **검증 방식** | **manual** - Creator가 사진을 직접 확인 후 승인/반려. **delayed** - AI 이미지 분석으로 키워드/객체 포함 여부 판정 (P1). |
| **UI 요소** | 카메라 촬영 화면 (인앱 카메라), 갤러리 선택(Creator 허용 시), 사진 미리보기, 미션 설명 오버레이, 제출 전 확인 화면 |
| **제약 조건** | 사진 최대 크기: 10MB/장. 최대 제출 수: Creator 설정 (기본 5장). 허용 형식: JPEG, PNG, HEIF. 갤러리 사진 허용 여부: Creator 설정 (기본: 인앱 촬영만). |
| **실패 시나리오** | 카메라 권한 미허용 → 권한 요청 안내. 이미지 용량 초과 → 자동 리사이즈 또는 재촬영 안내. AI 검증 실패 → "사진에서 필요한 요소를 확인할 수 없습니다" + 재제출 안내. 수동 검증 반려 → Creator 반려 사유 표시 + 재제출 안내. EXIF 데이터 누락/위변조 → 추가 검증 플래그 설정. |

### 4.3 QUEST (텍스트 미션)

| 항목 | 내용 |
|------|------|
| **정의** | 참여자가 주어진 질문이나 미션에 대해 텍스트로 답변을 제출하는 미션. |
| **입력 데이터 (Creator)** | 질문/미션 텍스트, 정답(auto 선택 시, 복수 정답 가능), 대소문자 구분 여부, 부분 일치 허용 여부, 힌트(선택), 최대 답변 길이 |
| **제출 데이터 (Participant)** | 텍스트 답변 |
| **검증 방식** | **auto** - 정답 문자열 완전/부분 일치 판정. **manual** - Creator가 서술형 답변을 직접 평가. **delayed** - AI 텍스트 분석으로 의미 유사도 판정 (P1). |
| **UI 요소** | 질문 표시 영역, 텍스트 입력 필드 (단답/장문 구분), 글자 수 카운터, 힌트 버튼 (사용 시 감점 설정 가능), 제출 버튼 |
| **제약 조건** | 답변 최대 길이: 단답형 100자, 서술형 2,000자. 정답 등록 시 복수 정답 최대 20개. 특수 문자 허용 여부 Creator 설정. |
| **실패 시나리오** | 정답 불일치(auto) → "정답이 아닙니다" + 재시도 안내 (재시도 횟수 Creator 설정). 빈 답변 제출 시도 → 입력 필수 안내. 글자 수 초과 → 초과 부분 잘림 경고. 수동 검증 반려 → Creator 반려 사유 + 재제출 안내. |

### 4.4 OX_QUIZ (참/거짓 퀴즈)

| 항목 | 내용 |
|------|------|

| **입력 데이터 (Creator)** | 퀴즈 진술문, 정답(O 또는 X), 해설(선택), 제한 시간(선택), 문제 이미지(선택) |

| **검증 방식** | **auto** - 선택 값과 정답 즉시 비교. |
| **UI 요소** | 진술문 표시 영역, O/X 대형 버튼, 제한 시간 타이머, 정답 후 해설 표시(Creator 설정), 정/오답 애니메이션 |

| **실패 시나리오** | 오답 선택 → 오답 표시 + 해설 표시(설정 시) + 재시도 안내 (재시도 횟수 Creator 설정). 제한 시간 초과 → 자동 오답 처리. 네트워크 지연으로 답변 전송 지연 → 클라이언트 측 타임스탬프 기준 유효성 판정. |

### 4.5 LIST (체크리스트)

| **제출 데이터 (Participant)** | 각 항목의 체크 상태, 항목별 증거 데이터(요구 시) |

| **실패 시나리오** | 필수 항목 미체크 시 제출 → 미완료 항목 하이라이트 표시. 순차 강제 위반 시도 → "이전 항목을 먼저 완료해 주세요" 안내. 항목 증거 누락 → 해당 항목 증거 제출 요구. 부분 완료 후 제한 시간 초과 → 완료된 항목만 인정 또는 전체 실패 (Creator 설정). |

## 5. 데이터 객체 개요

### 5.1 Clue (클루)

| 필드명 | 타입 | 필수 | 설명 |
|--------|------|:----:|------|
| `id` | UUID | O | 고유 식별자 |
| `title` | String(100) | O | Clue 제목 |
| `description` | String(2000) | O | Clue 상세 설명 |
| `creator_id` | UUID (FK → User) | O | 생성자 ID |
| `category` | Enum | O | 카테고리 (HIDE_AND_SEEK, TREASURE_HUNT, MT, SCHOOL_TRIP, WORKSHOP, QUIZ, BROADCAST, LIFE_HELP, ATTENDANCE, ASSESSMENT, PROMOTION, OTHER) |
| `status` | Enum | O | 상태 (DRAFT, PENDING_APPROVAL, APPROVED, REJECTED, ACTIVE, PAUSED, COMPLETED, CANCELLED) |
| `visibility` | Enum | O | 공개 범위 (PUBLIC, PRIVATE, CLAN_ONLY, LINK_ONLY) |
| `participation_type` | Enum | O | 참여 유형 (INDIVIDUAL, CLAN) |
| `max_participants` | Integer | - | 최대 참여 인원 (null = 무제한) |
| `step_order` | Enum | O | Step 수행 순서 (SEQUENTIAL, RANDOM, FREE) |
| `start_at` | DateTime | O | 시작 일시 |
| `end_at` | DateTime | O | 종료 일시 |
| `location` | GeoJSON | - | 대표 활동 위치 (지도 표시용) |
| `cover_image_url` | String | - | 커버 이미지 URL |
| `tags` | String[] | - | 검색용 태그 |
| `is_minor_friendly` | Boolean | O | 미성년자 참여 가능 여부 |
| `retry_policy` | JSON | O | 재시도 정책 (max_retries, cooldown_seconds) |
| `reward_summary` | JSON | - | 보상 요약 정보 |
| `approval_note` | String(500) | - | 관리자 승인/반려 사유 |
| `created_at` | DateTime | O | 생성 일시 |
| `updated_at` | DateTime | O | 수정 일시 |

**관계:** Clue 1 → N Step, Clue 1 → N Reward, Clue N ← M User(참여), Clue 1 → N Report

### 5.2 Step (스텝)

| 필드명 | 타입 | 필수 | 설명 |
|--------|------|:----:|------|
| `id` | UUID | O | 고유 식별자 |
| `clue_id` | UUID (FK → Clue) | O | 소속 Clue ID |
| `type` | Enum | O | Step 타입 (CHECKPOINT, SNAPSHOT, QUEST, OX_QUIZ, LIST, BOARD, PANORAMA, FACIAL) |
| `title` | String(100) | O | Step 제목 |
| `description` | String(1000) | O | Step 설명 |
| `order_index` | Integer | O | 순서 인덱스 |
| `config` | JSON | O | 타입별 설정 데이터 (좌표, 정답, 체크리스트 등) |
| `validation_type` | Enum | O | 검증 방식 (AUTO, DELAYED, MANUAL) |
| `time_limit_seconds` | Integer | - | 제한 시간 (null = 무제한) |
| `hint` | JSON | - | 힌트 데이터 (text, image_url, penalty_points) |
| `points` | Integer | O | 완료 시 획득 포인트 |
| `is_required` | Boolean | O | 필수 Step 여부 |
| `created_at` | DateTime | O | 생성 일시 |
| `updated_at` | DateTime | O | 수정 일시 |

**관계:** Step N → 1 Clue, Step 1 → N Evidence

### 5.3 Evidence (증거)

| 필드명 | 타입 | 필수 | 설명 |
|--------|------|:----:|------|
| `id` | UUID | O | 고유 식별자 |
| `step_id` | UUID (FK → Step) | O | 대상 Step ID |
| `user_id` | UUID (FK → User) | O | 제출자 ID |

## 6. 승인/반려/조건부 승인 기준

### 6.1 Clue 승인 프로세스 흐름

```
Creator → Clue 생성(DRAFT) → 승인 요청(PENDING_APPROVAL)
    ├── 자동 승인 조건 충족 → APPROVED
    ├── 수동 검토 필요 → Admin 검토 큐 진입
    │     ├── 승인 → APPROVED
    │     ├── 조건부 승인 → Creator 수정 요청 → 재검토
    │     └── 반려 → REJECTED (사유 기재)
    └── 자동 반려 조건 해당 → REJECTED (자동 사유)
```

### 6.2 자동 승인 조건

아래 조건을 **모두** 충족하는 경우 시스템이 자동으로 승인 처리한다.

| # | 조건 | 기준 |
|---|------|------|
| 1 | Creator 등급 | 인증(VERIFIED) 이상 |
| 2 | 보상 유형 | 포인트 또는 뱃지만 포함 (쿠폰/경품/추첨권 미포함) |
| 3 | 경품 금액 | 보상에 금전적 가치 없음 (0원) |
| 4 | 미성년자 관련 | FACIAL Step 미포함, 미성년자 특별 보호 대상 아님 |
| 5 | 콘텐츠 검사 | AI 유해 콘텐츠 탐지 결과 CLEAN |
| 6 | Step 수 | 1개 이상 50개 이하 |
| 7 | 기간 | 시작일이 현재 시점 이후, 기간 365일 이내 |
| 8 | 방송 연동 | 스트리밍 연동 미사용 |
| 9 | 위치 | 방문형 미션 시 국내 좌표 범위 이내 |
| 10 | 과거 이력 | Creator의 최근 반려/신고 이력 0건 (30일 기준) |

### 6.3 수동 검토 트리거 (Admin 검토 큐 진입)

아래 조건 중 **하나라도** 해당하면 수동 검토 대상이 된다.

| # | 트리거 조건 | 사유 | 우선순위 |
|---|------------|------|----------|
| 1 | **경품/상금 포함** | 보상에 쿠폰, 경품, 추첨권이 포함되거나 금전적 가치가 있는 경우 | HIGH |
| 2 | **방송 연동** | 스트리밍 플랫폼과 연동된 Clue | HIGH |
| 3 | **미성년자 대상** | `is_minor_friendly = true`이면서 위치 기반 Step 포함 | HIGH |
| 4 | **방문형 미션 (가정/사유지)** | CHECKPOINT 좌표가 주거지역/사유지로 판정되는 경우 | CRITICAL |
| 5 | **FACIAL Step 포함** | 얼굴 인식 Step이 포함된 경우 (개인정보 심사 필요) | CRITICAL |
| 6 | **신규 Creator** | Creator 등급이 BASIC (미인증) | MEDIUM |
| 7 | **대규모 참여** | max_participants > 500 | MEDIUM |
| 8 | **AI 콘텐츠 경고** | AI 콘텐츠 분석에서 WARNING 등급 판정 | MEDIUM |
| 9 | **과거 반려 이력** | Creator의 30일 내 반려 1건 이상 | MEDIUM |
| 10 | **외부 링크 포함** | 설명 또는 Step에 외부 URL 포함 | LOW |

### 6.4 자동 반려 조건

아래 조건 중 **하나라도** 해당하면 즉시 자동 반려 처리한다.

| # | 반려 조건 | 자동 반려 사유 메시지 |
|---|----------|---------------------|
| 1 | 금지어 포함 | "금지된 표현이 포함되어 있습니다. 내용을 수정 후 다시 제출해 주세요." |
| 2 | AI 유해 콘텐츠 BLOCK 판정 | "유해 콘텐츠가 감지되었습니다. 커뮤니티 가이드라인을 확인해 주세요." |
| 3 | 동일 Clue 중복 제출 (유사도 90% 이상) | "동일하거나 매우 유사한 Clue가 이미 존재합니다." |
| 4 | Creator 계정 정지 상태 | "현재 계정 상태로는 Clue를 등록할 수 없습니다." |
| 5 | Step 0개 | "최소 1개 이상의 Step을 추가해야 합니다." |
| 6 | 종료일이 시작일 이전 | "종료 일시가 시작 일시보다 이전입니다." |
| 7 | 필수 필드 누락 | "필수 입력 항목이 누락되었습니다: [필드명]" |

### 6.5 조건부 승인

Admin이 Clue를 부분적으로 승인하되 특정 수정을 요구하는 경우.

| 상황 | 조건부 승인 내용 | Creator 대응 |
|------|-----------------|-------------|
| 보상 금액 과다 | "경품 가치를 XX원 이하로 조정해 주세요." | 보상 수정 후 재제출 |
| 부적절한 이미지 | "커버 이미지 또는 Step 이미지를 교체해 주세요." | 이미지 교체 후 재제출 |
| 위치 안전 우려 | "CHECKPOINT 위치를 공공 장소로 변경해 주세요." | 위치 수정 후 재제출 |
| 설명 보완 필요 | "참여 안내 사항을 더 구체적으로 작성해 주세요." | 설명 보완 후 재제출 |
| FACIAL 동의 미확인 | "대상 인물의 초상권 동의서를 첨부해 주세요." | 동의서 첨부 후 재제출 |
| 미성년자 보호 조치 부족 | "미성년자 참여 관련 안전 가이드라인을 추가해 주세요." | 가이드라인 추가 후 재제출 |

조건부 승인 시 Creator에게 수정 사항이 알림으로 전달되며, 수정 후 재제출 시 동일 Admin에게 우선 배정된다. 재제출 기한은 **7일**이며 기한 초과 시 자동 반려 처리된다.

### 6.6 Evidence 검증 규칙

| Step 타입 | 자동 검증 기준 | 수동 검증 전환 조건 |
|-----------|---------------|-------------------|
| CHECKPOINT | GPS 거리 ≤ 허용 반경 AND 정확도 ≤ 30m AND Mock GPS 미감지 | GPS 정확도 > 30m, Mock GPS 의심 |
| SNAPSHOT | N/A (기본 수동) | 항상 수동 또는 AI 검증 |

| QUEST (서술) | N/A (기본 수동) | 항상 수동 또는 AI 검증 |
| OX_QUIZ | O/X 정답 일치 | N/A |
| LIST | 필수 항목 전체 체크 AND 최소 완료 수 충족 | 항목별 증거 포함 시 수동 전환 |

| FACIAL | N/A (기본 AI + 수동) | 항상 수동 확인 필수 |
