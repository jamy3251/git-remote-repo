## 2. Phase 2 — 소셜 + 수익화 (출시 후 3개월)

### 2.1 클랜 시스템
| 기능 | 설명 | 우선순위 |
|------|------|---------|
| 클랜 생성/가입 | 팀 단위 미션 참여 | P1 |
| 클랜 vs 클랜 | 팀 대항전 미션 | P1 |
| 클랜 채팅 | 실시간 그룹 채팅 | P2 |
| 클랜 랭킹 | 주간/월간 클랜 순위 | P1 |

**기존 준비 상태**: DB에 `clans`, `clan_members` 테이블 + RLS 이미 존재. Flutter 모델 (`clan.dart`) 완성. UI만 구축하면 됨.

### 2.2 결제 시스템
| 기능 | 설명 | 우선순위 |
|------|------|---------|
| 유료 미션 참가비 | 참가비 결제 → 상금 풀 | P1 |
| 크리에이터 정산 | 수익 배분 (커미션 모델) | P1 |
| 소상공인 광고비 | 미션 등록 광고 요금 | P2 |
| 포인트 현금화 | 포인트 → 계좌 이체 | P2 |

**필요 기술**: PG사 연동 (토스페이먼츠/아임포트), 정산 배치 시스템

### 2.3 AI 검증
| 기능 | 설명 | 우선순위 |
|------|------|---------|
| 이미지 AI 검증 | SNAPSHOT 사진의 적합성 자동 판정 | P1 |
| 텍스트 AI 검증 | QUEST 답변의 관련성 판정 | P2 |
| AI 콘텐츠 모더레이션 | 부적절 사진/텍스트 자동 필터링 | P1 |
| GPS 스푸핑 탐지 | 위치 조작 감지 (EXIF + 이동 패턴) | P1 |

**기술 방향**: Claude API 또는 GPT-4o Vision으로 이미지 분석, 서버사이드 Edge Function

### 2.4 오프라인 모드
| 기능 | 설명 | 우선순위 |
|------|------|---------|
| Evidence 로컬 큐잉 | 네트워크 끊김 시 로컬 저장 → 복구 시 자동 전송 | P1 |
| 미션 데이터 캐싱 | 진행 중 미션 데이터 로컬 저장 | P1 |
| 오프라인 맵 | 미션 지역 지도 미리 다운로드 | P2 |

**기존 준비 상태**: `connectivity_plus` 패키지 이미 설치됨. Eng Review에서 critical gap으로 식별.

### 2.5 크리에이터 도구
| 기능 | 설명 | 우선순위 |
|------|------|---------|
| 크리에이터 대시보드 | 참여율, 완주율, 이탈 지점 분석 | P1 |
| 미션 템플릿 | 인기 미션 패턴 재사용 | P1 |
| AI 미션 생성기 | "MT 보물찾기" 입력 → 5스텝 자동 생성 | P2 |
| 미션 복제 | 기존 미션 1탭 복사 | P1 |

### 2.6 추가 스텝 타입
| 타입 | 설명 | 우선순위 |
|------|------|---------|
| BOARD | 참여자 간 정보 공유 게시판 | P1 |
| QR_SCAN | QR 코드 스캔 전용 스텝 | P1 |

**기존 준비 상태**: DB 스키마에 BOARD 타입 이미 정의됨. `QrScannerWidget` 구현 완료.

### 2.7 분쟁/이의제기
| 기능 | 설명 | 우선순위 |
|------|------|---------|
| 이의 신청 | 반려된 인증에 대한 재심 요청 | P1 |
| 관리자 중재 | 분쟁 심사 + 결정 | P1 |

## 3. Phase 3 — 확장 + B2B (출시 후 6개월)

### 3.1 고급 스텝 타입
| 타입 | 설명 | 기술 |
|------|------|------|
| PANORAMA | 360도 파노라마 사진 미션 | 전용 카메라 UI |
| FACIAL | 얼굴 인식 출석/본인 확인 | ML Kit Face Detection |
| AR | 증강현실 힌트/상호작용 | ARCore/ARKit |

### 3.2 스트리머 연동
| 기능 | 설명 | 기술 |
|------|------|------|
| OBS 오버레이 | 방송 화면에 미션 진행 상황 표시 | WebSocket 연동 |
| 실시간 참여 | 시청자가 방송 중 미션에 참여 | 딥링크 + 실시간 피드 |
| 방송 미션 타입 | is_broadcast_type 전용 승인 | 관리자 사전 승인 |

**기존 준비 상태**: DB에 `is_broadcast_type` 필드 이미 존재.

### 3.3 B2B 화이트라벨
| 기능 | 설명 | 대상 |
|------|------|------|
| 학교 전용 모드 | 출석체크, 현장 평가, 수학여행 | 초/중/고/대학 |
| 기업 전용 모드 | 워크숍, 팀빌딩, 온보딩 | 기업 HR |
| 매장 전용 모드 | 방문 미션, 쿠폰 발급, 집객 | 소상공인 |

### 3.4 글로벌화
| 기능 | 설명 | 우선순위 |
|------|------|---------|
| 다국어 지원 | 영어, 일본어, 중국어 | P1 |
| i18n 인프라 | Flutter intl + Supabase 다국어 콘텐츠 | P1 |
| 해외 결제 | Stripe 연동 | P2 |

### 3.5 고급 분석
| 기능 | 설명 |
|------|------|
| 사용자 행동 히트맵 | 미션 내 이동 패턴 시각화 |
| 퍼널 분석 | 미션 스텝별 이탈률 |
| 크리에이터 인사이트 | 어떤 미션이 왜 인기 있는지 |
| A/B 테스트 | 미션 설명/보상 변경 효과 측정 |

## 4. 기능 우선순위 매트릭스

```
                     높은 영향
                        │
    ┌───────────────────┼───────────────────┐
    │  클랜 시스템        │  결제 시스템       │
    │  AI 검증           │  크리에이터 대시보드 │
    │  오프라인 모드      │  분쟁/이의제기      │
    │                   │                    │
낮은 ─────────────────────────────────────── 높은
노력 │                   │                    │ 노력
    │  미션 템플릿        │  B2B 화이트라벨    │
    │  QR 스캔 스텝      │  AR 미션           │
    │  미션 복제         │  스트리머 연동       │
    │                   │  글로벌화           │
    └───────────────────┼───────────────────┘
                        │
                     낮은 영향
```

**즉시 실행 (높은 영향 + 낮은 노력):**
- 미션 템플릿, QR 스캔 스텝, 미션 복제

**전략적 투자 (높은 영향 + 높은 노력):**
- 결제 시스템, 크리에이터 대시보드, B2B 화이트라벨

**빠른 승리 (낮은 영향 + 낮은 노력):**
- BOARD 스텝, 클랜 채팅

**장기 비전 (낮은 영향 + 높은 노력):**
- AR 미션, 스트리머 연동, 글로벌화

## 6. 기술 부채 해소 계획

### Phase 2에서 해결
| 항목 | 현재 상태 | 해결 방향 |
|------|----------|----------|
| mockito 빌드 충돌 | dev_dependency 비활성화 | 버전 업그레이드 또는 교체 |
| Widget 테스트 부재 | Unit 테스트만 36개 | Widget + Integration 테스트 추가 |
| Supabase Pro 플랜 | 무료 플랜 (200 connection) | 대규모 이벤트 대비 Pro 전환 |
| iOS 빌드 | Android only | macOS CI 또는 Codemagic |
| CI/CD | 수동 빌드 | GitHub Actions 파이프라인 |
| Freezed 코드 생성 | 수동 실행 | CI에서 자동화 |

### Phase 3에서 해결
| 항목 | 설명 |
|------|------|
| 에러 모니터링 | Sentry / Firebase Crashlytics 통합 |
| 분석 | Firebase Analytics / Amplitude 연동 |
| 성능 모니터링 | Firebase Performance |
| 서버사이드 로직 | Supabase Edge Functions → 별도 서버 검토 |
