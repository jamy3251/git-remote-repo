| TB-04 | 검증 로직 복잡도 증가 | 자동/지연/수동 검증 + AI 검증 혼합 시 상태 관리 복잡 | P1 이후 | 상태 머신(State Machine) 패턴 도입 |
| TB-05 | 위치 기반 쿼리 성능 | 사용자/Clue 증가 시 "내 주변 Clue" 검색 성능 저하 | 출시 후 | 공간 인덱스(PostGIS/GeoHash), 캐싱 |
| TB-06 | 알림 시스템 복잡도 | Clue 상태 변경, 검증 결과, 커뮤니티 활동 등 알림 종류 증가 | P1 이후 | 알림 서비스 분리, 우선순위 관리 |
| TB-07 | 테스트 커버리지 부족 | MVP 속도 우선 개발 시 테스트 작성 부족 | 알파 이후 | MVP 이후 테스트 보강 스프린트 |
| TB-08 | 관리자 콘솔 기능 부족 | 초기 최소 기능으로 출시 후 운영팀 수동 작업 증가 | 출시 후 | 운영 피드백 기반 점진적 개선 |
| TB-09 | 다국어/지역화 후적용 비용 | 초기 한국어 하드코딩 시 추후 i18n 적용 비용 증가 | P2 | MVP부터 문자열 외부화 최소 적용 |
| TB-10 | 모놀리식 → 마이크로서비스 전환 | 초기 모놀리식으로 빠르게 개발 후 확장 시 전환 필요 | 사용자 10만 이상 | 도메인별 모듈 분리를 초기부터 고려 |
