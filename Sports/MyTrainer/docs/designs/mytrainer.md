## Problem Statement
헬스 기록을 손으로 하는 사람들은 세트 사이에 폰을 두드리는 게 귀찮아서 기록을 빼먹거나 나중에 몰아서 적는다. 기록이 비면 1RM 추이, 실패 지점, 다음 주 무게 판단이 모두 감에 의존하게 된다. AI 루틴 추천은 기록이 쌓여야만 작동하므로, 먼저 풀어야 할 문제는 "기록이 안 쌓인다"이다.

## Demand Evidence
- 본인과 헬스 친구들이 지금 수기로 기록 중이며, 가장 큰 불편은 "기록 자체가 귀찮음".
- 결제·이탈 같은 행동 근거는 아직 없음. 현재 근거 수준은 "본인 그룹의 수기 기록 행동"이다.

## Status Quo
- 메모장/수기로 종목·무게·횟수 기록, 빠지는 세트·날짜가 생김.
- 시장 대안: Strong·Hevy(기록), Fitbod(AI 무게 추천), 워치 반복 자동 세기, 챌린저스류(인증). 기능 자체는 전부 존재하므로 차별점은 기능 목록이 아니라 "한 헬스장 친구 그룹에서 기록 누락을 없애는 것".
- 가정(미검증): 워치 반복 자동 세기는 근력 운동에서 정확도가 낮다는 평이 많다. 출처·직접 테스트 없음.

## Target User & Narrowest Wedge
- 첫 사용자: 본인 + 같은 헬스장을 다니는 친구들(소규모 파티).
- 가장 좁은 쐐기: 헬스장 한 곳 전용. 도착하면 출석이 자동으로 찍히고, 기구를 찍거나 탭하면 그 종목의 지난 기록이 미리 채워져 "같은 세트 반복" 한 탭으로 기록되는 것.

## Constraints
- 헬스장 한 곳에서만 사용 (사용자 결정, 2026-10-08).
- 안드로이드 우선, Flutter. 온디바이스 ML.
- 실내 GPS 오차 10~30m 이상 → GPS로는 "헬스장에 왔다"까지만 판정 가능, 기구 구분 불가.
- 헬스장은 지하 등 통신이 약할 수 있음 → 기록·매칭은 오프라인에서 완전히 동작해야 함.
- 자세 교정은 정확도·부상 책임 문제로 v1 제외.

## Premises (모두 동의)
1. 핵심 문제는 기록 누락. AI 루틴·다음 무게 추천은 기록 2~3주 누적 후의 두 번째 단계.
2. 첫 사용자는 본인 + 헬스 친구들. 친구가 본다는 사회적 압력이 기록 동기. **(미검증 가정 — The Assignment와 테스트 계획에서 확인)**
3. 자세 교정 v1 제외. 카메라는 반복 세기·기구로 종목 판별에 사용.
4. 인증은 "등록 헬스장 지오펜스 + 앱 내 촬영" 수준이면 친구 사이에 충분 (완전한 위조 방지는 목표 아님).
5. 안드로이드 먼저, Flutter + 온디바이스 ML.
6. 공모전 근거 = 같은 친구들의 사용 전/후 기록 누락률 비교.

## Approaches Considered
- **A. 원탭 기록 + 파티** — 채택(기반).
- **B. 전체 비전** — 제외한 부분: 매 세트 폰을 거치해 카메라로 자동 기록하는 흐름, 자세 교정, AI 주간 루틴. 이유: 매 세트 폰 거치가 오히려 마찰을 키우고 정확도 검증에 수 주 소요. 단, B의 "기구 인식"은 **사진 한 장으로 기구를 고르는 용도**로 축소해 A에 편입(사용자가 세션 중 "기구 최초 사진 + GPS로 자동 매칭"을 요청). 세트마다 카메라를 켜는 것이 아니라 기구를 바꿀 때 한 번만 찍는다.
- **C. 스포터 모드** — 채택(스쿼트 1종목 데모).

## Recommended Approach: A + C(스쿼트 1종목)

### 1. 출석 자동 인증 (GPS 지오펜스)
- 최초 설정: 헬스장 안에서 "여기가 내 헬스장" 버튼 → 30초간 fused location 샘플 여러 개를 평균해 중심점 계산(사진 EXIF는 쓰지 않음: 앱 카메라 촬영본에는 GPS EXIF가 없고, 안드로이드는 ACCESS_MEDIA_LOCATION 없이 위치를 지움). 반경 기본 80m, 지도에서 중심·반경 수동 조정 가능. 파티원은 같은 헬스장 설정을 공유.
- 권한: ACCESS_FINE_LOCATION + ACCESS_BACKGROUND_LOCATION. 온보딩에서 이유 설명 후 "항상 허용" 요청, 배터리 최적화 예외 안내.
- 이벤트: Android Geofencing API 진입/이탈로 입장·퇴장 시각 기록. Doze 등으로 이벤트가 늦거나 누락될 수 있으므로 보완 규칙:
  - 진입 이벤트가 없어도, 지오펜스 안에서 세트를 기록하면 그 시점을 체크인으로 간주.
  - 이탈 이벤트가 없으면 마지막 세트 기록 후 90분에 세션 자동 종료(최대 4시간 상한).
  - 수동 체크인 버튼 제공, 피드에 "수동" 표시.
  - 세트 기록과 무관한 체류 감지: 지오펜스 DWELL 전이(loiteringDelay 20분)를 함께 등록하고, 앱이 켜져 있지 않아도 15분 간격 저빈도 위치 확인(WorkManager)으로 안/밖을 판정. 세션 종료는 다음 번 지오펜스 밖 위치가 확인된 시점, 확인이 없으면 4시간 상한.
  - 지표 투명성: "세트 기록으로만 복구된 체류일" 수를 따로 집계해 보고(분모 편향을 눈에 보이게).
- 위치 위조 표시: API 31+ `Location.isMock()`, 그 이하 `isFromMockProvider()`. 위조로 판정된 출석은 파티 피드의 해당 출석 항목에 "위치 확인 안 됨" 표시. 차단은 하지 않음.
- **출석 전용 모드**(v1 빌드 항목): 기록·피드 기능을 끄고 지오펜스 체류일만 수집하는 모드. 베이스라인 2주 동안 사용. 화면은 "오늘 헬스장 체류함 / 기록했나요? 예·아니오" 한 장뿐.
- 두 가지 정의를 분리:
  - **헬스장 체류일** = 지오펜스 안 체류 20분 이상인 날(세트 기록 여부 무관). 지표 분모로만 사용.
  - **오늘 운동함(피드 표시)** = 체류일 + 세트 기록 1개 이상.

### 2. 개인정보·촬영 정책
- 서버로 가는 위치 정보는 출석 여부·입장/퇴장 시각뿐. 좌표는 기기 밖으로 나가지 않음(헬스장 중심점만 파티 설정으로 공유).
- 파티 가입 시 출석 공유 명시적 동의(opt-in). 출석 상태 숨기기, 파티 탈퇴 시 내 출석·기록 공유분 삭제. 탈퇴자가 등록한 기구는 파티 소유로 이전되어 남음(매칭에 영향 없음). 서버 보관 출석 데이터는 탈퇴 시 즉시, 그 외 1년 후 삭제.
- 기구 등록 사진: 사람이 나오지 않게 찍도록 촬영 가이드 표시. 공유되는 것은 임베딩 벡터와 저해상도 썸네일뿐이며, 썸네일 업로드 전 ML Kit 얼굴 감지로 얼굴을 블러 처리.
- 스포터 영상: 기본은 촬영자 폰에만 남고 업로드하지 않음(아래 4절).
- 헬스장 촬영 규정은 사장님께 스티커 질문과 함께 확인(The Assignment).

### 3. 기구 매칭과 원탭 기록
- GPS로는 기구를 구분할 수 없다(기구 간 1~3m, 실내 오차 10m+). 기구 판별은 사진으로 한다.
- 최초 등록: 기구마다 사진 2~3장 + 가능한 종목 지정(예: 스미스머신 → 스쿼트·벤치). 온디바이스 이미지 임베딩(TFLite MobileNetV3 특징 벡터)으로 저장, 파티원과 공유. 등록 시 중복 검사: 기존 기구와 유사도가 임계값 이상이면 "기존 기구에 사진 추가"를 먼저 제안. 중복 병합·삭제는 등록자 또는 파티장이 할 수 있음. 같은 모델 기구가 여러 대면 하나의 "기구 그룹"으로 묶음.
- 사용 시: 기구를 바꿀 때 한 장 촬영 → 로컬에 캐시된 등록 임베딩(기구 30~50개 × 사진 2~3장 = 60~150개)과 코사인 유사도 비교. 기구별 점수는 그 기구 사진들 중 최대 유사도로 매기고 순위를 정함. 1위가 임계값 이상이면 자동 선택(확인 탭 1회), 미만이면 상위 3개 중 선택.
- 자가 학습은 v1에서 하지 않음(잘못 고른 샘플이 파티 전체 매칭을 오염시킬 위험). 기구 재등록·사진 삭제는 등록자 또는 파티장이 수동으로.
- 종목 결정: 기구에 종목이 여러 개면 내가 그 기구에서 마지막으로 한 종목이 기본값, 바꿀 때만 탭.
- 미리 채우기: 기록은 **사용자별·종목별**로 저장하고, 그 종목의 직전 세션 무게·횟수를 채움. "같은 세트" 한 탭, ±2.5kg / ±1회 버튼.
- 실패 지점: 기본값은 "성공". 실패했을 때만 "N회째 실패"를 탭.
- 추정 1RM: Epley(무게 × (1 + 완료 반복/30)). 실패 세트는 완료한 반복만 사용, 완료 반복 10회 이하 세트만 계산. 종목별 추이 그래프.
- 휴식 타이머 자동 시작.
- 옵션(사장님 허락 시): 기구에 NFC 태그/QR 스티커. 탭 한 번 = 기구 식별, 정확도 ~100%. 사진 매칭을 대체.

### 4. 스포터 모드 (스쿼트 1종목 데모)
- 흐름: 촬영자가 "스포터 모드" → 같은 파티의 지금 체크인한 멤버 목록에서 리프터 선택(오프라인이면 캐시된 전체 파티원 목록에서 선택) → 측면·전신이 나오게 2~3m 거리에서 촬영(화면에 가이드 실루엣) → 반복 수 자동 카운트.
- 포즈 추정: `google_mlkit_pose_detection` 패키지 사용(네이티브 ML Kit를 감싼 커뮤니티 플러그인, 직접 플랫폼 채널을 짤 필요 없음. 유지보수·버전 호환 위험은 있음). 엉덩이-무릎-발목 각도로 하강/상승 상태 머신을 돌려 반복 수 계산. 예상 작업량: 카운터 + 실측 튜닝 human ~1주 / CC ~1~2일.
- 전달: 결과(종목, 반복 수, 촬영자, 시각)만 백엔드로 리프터에게 전송. 리프터 앱에 "친구 OO가 스쿼트 8회 기록" 알림 → 리프터가 무게 확인·횟수 수정 후 저장해야 기록에 반영. 피드에 "촬영자 인증" 표시.
- 오프라인: 촬영자 폰에 결과를 큐로 저장, 연결되면 전송. 리프터가 24시간 내 확인하지 않으면 만료.
- 영상: 촬영자 폰에만 보관, 리프터가 원하면 직접 공유(근거리 공유/메신저). 앱은 업로드하지 않음.
- 자세 판정은 하지 않음(교정 문구 없음).

### 5. 오프라인·동기화
- 세트 기록, 기구 매칭, 1RM 계산은 로컬 DB(SQLite/Drift)와 캐시된 임베딩만으로 동작.
- 서버 동기화는 변경 큐로 처리. 기록은 사용자 본인만 쓰므로 충돌이 거의 없고, 같은 레코드 충돌 시 마지막 수정 우선. 기구 등록은 추가 전용(삭제는 등록자만).

### v1 범위에서 뺀 것
- 주간 리뷰(규칙 기반 다음 무게 + LLM 설명 + 체중·회복 자가 입력): 2주 검증 기간 안에 의미 있게 동작하지 않고, 추가 입력이 기록 마찰을 늘림. 검증 후 v1.1. 규칙(이중 진행법, 2주 연속 같은 지점 실패 시 디로드)은 그대로 두고, LLM은 숫자를 만들지 않고 설명만 한다.

## Open Questions
- 헬스장 사장님이 NFC/QR 스티커 부착·촬영을 허락할지.
- 친구 몇 명이 2주 테스트에 참여 가능한지(최소 4명 목표).
- 기구 사진 매칭 정확도: 조명·각도 변화 시 1위 정답률(목표 85% 이상)과 자동 선택 임계값.
- 공모전 마감일·심사 기준.

## Success Criteria
- 참가자: 베이스라인에 참여한 같은 친구 4명 이상, 앱 2주 사용.
- **기록 누락률**: 같은 사람·같은 방식으로 사용 전/후 비교.
  - 사용 전 2주(베이스라인): 앱을 출석 전용 모드로 설치(기록 기능 꺼짐)해 헬스장 체류일을 자동 수집. 체류일마다 당일 밤 알림으로 "오늘 수기로 기록했나요?"를 묻고, 주말에 메모 스크린샷으로 진행자(본인)가 대조 확인. 체류일 중 수기 기록이 있는 날 비율을 계산.
  - 사용 후 2주: 헬스장 체류일 중 앱에 세트 기록이 있는 날 비율. 목표 90% 이상은 2주 전체 기준, 베이스라인 대비 상승폭 보고.
- **세트당 탭 수**: 기구·종목이 정해진 뒤 한 세트 기록에 드는 탭(같은 세트 1탭 + 필요 시 ±조정/실패 입력). 평균 2회 이하. 기구 식별 탭(촬영+확인)은 기구당 별도 집계, 평균 3회 이하.
- 기구 사진 매칭 1위 정답률 85% 이상(등록 기구 기준).
- 스포터 모드 스쿼트 반복 카운트 오차 ±1회 이내 90% 이상(측면·전신 촬영 조건).
