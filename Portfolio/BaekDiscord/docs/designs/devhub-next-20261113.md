## 4. 제안 계획

### P0. 정체성 결정과 문서 정리
- 제품을 **"DevHub 관제: AI 코딩 에이전트 관제탑"**(B)으로 재정의하고, 팀 다이제스트(A)는 `web/` 안의 보관 기능으로 격리한다(코드 유지, 내비게이션에서 뒤로, M0가 열리면 재개). 최종 결정은 사용자 몫.
- `docs/designs/devhub-control.md`를 새 단일 진실 문서로 쓴다(아키텍처, 상태 모델, 보안 모델, 결정 기록). 기존 addendum은 이력으로 남긴다.
- 폴더 이동을 git에 반영(`git mv` 상당의 커밋)하고 경로 가정(README, `devhub-runner` 스킬, cwd 루트 기본값)을 고친다.

### P1. 구조 보완
- `packages/protocol` 워크스페이스로 프로토콜 타입을 한 벌로 만들고 runner·web이 import. 메시지 스키마를 런타임 검증(zod 등 기존 의존성 확인 후)하고, 안드로이드가 쓰는 메시지 부분집합을 JSON 스키마로 뽑아 계약 테스트.
- `server.ts`를 기능 모듈 등록 방식으로 분해(`routes/sessions`, `routes/worklog`, `routes/products`, `ws/hub`). 기능 하나 추가가 파일 한 개 추가로 끝나게.
- 저장 계층: `runner/.data`를 단일 SQLite(better-sqlite3 또는 node:sqlite)로 옮겨 세션 메타·이벤트·작업 내역·제품·교차검증 결과를 한 곳에. jsonl은 가져오기 후 폐기.
- 러너 재시작 내구성: 세션 메타·목표·정책·링버퍼 꼬리를 저장하고, 재시작 후 "끊긴 세션"으로 보여 주며 `claude --resume`으로 이어 붙이는 버튼.

### P2. 슈퍼바이저 신호 품질
- Claude Code hooks(`Notification`, `Stop`, `PreToolUse`)와 세션 jsonl, Codex의 구조화 출력을 1차 신호로 쓰고, 출력 꼬리 정규식은 그 외 CLI용 폴백으로 내린다.
- 판단 기록(상태 전이, 엔진 응답, 사람이 승인/무시/수정한 결과)을 저장해 **오판율**을 대시보드에 표시. 기록에서 골든 세트를 뽑아 `npm run eval:supervisor`로 휴리스틱·프롬프트 변경을 회귀 검증.
- 자율 모드 안전: 위험 패턴을 출력 텍스트가 아니라 **실행하려는 도구 호출**(hook의 tool_input) 기준으로 판정.

### P3. 보안
- 기기별 토큰: QR은 1회용 짧은 수명 페어링 코드, 교환 후 기기 토큰 발급, 대시보드에서 기기 목록·폐기. 터널 세션에는 읽기 전용/입력 가능/세션 생성 권한 단계.
- WS 인증을 쿼리 문자열에서 첫 메시지 또는 서브프로토콜로 이동. 터널이 열려 있는 동안 상단에 상시 표시 + 자동 닫힘 타이머.
- 감사 로그에 기기 id 기록.

### P4. 기능 추가 후보
- **작업 큐와 예산**: 세션 동시 상한(메모리 부족 이력)에 맞춘 대기열, 작업별 토큰·시간 예산, 초과 시 정지.
- **worktree 격리**: 같은 저장소에 여러 에이전트를 붙일 때 세션마다 git worktree를 만들어 충돌 방지, 끝나면 diff 검토 → 병합/폐기.
- **하루 브리핑**: 작업 내역·교차검증·제품 상태를 모아 아침에 "어제 한 일 / 오늘 손볼 것" 한 화면(원래 다이제스트 렌더 코드 재사용).
- **지시 템플릿**: 자주 쓰는 지시서를 저장·변수 치환.
- **비용 대시보드**: 엔진별·세션별 토큰과 추정 비용 추이.

### P5. 디자인
대상 화면 파일: `web/app/control/control-view.tsx`, `web/components/control/session-card.tsx`, `web/components/control/feed.tsx`, `web/components/control/overview.tsx`, `web/components/control/terminal-screen.tsx`, `web/components/products/products-view.tsx`, `web/components/nav.tsx`, `web/app/page.tsx`.
- `/control` 정보 구조 재정리: 폰 하단 탭이 대화·세션·새 작업·내역·제품·난제·앱으로 늘었다. 1차 탭 4개로 줄이고 나머지는 "더 보기"로.
- 상태 색·아이콘·용어(입력 대기/확인 필요/제안)를 한 표로 고정한 디자인 토큰 문서. 빈 상태·오류 상태·끊김 상태 화면 정의.

- 순서(두 리뷰어 지적으로 재배치. 오늘 있는 위험과 체감 가치를 앞에, 리팩터링은 필요할 때): 1차 = 폴더 이동 커밋(사용자 승인이 선행 조건) → CI와 실패 테스트 → 쿼리 토큰 제거, 터널 전용 포트, 터널 표시와 자동 닫힘 → 무인 장시간 폰 시험(사용자) → 공식 기능 대비 위치 관문과 hook 확인 스파이크(각 반나절) → 판단 기록 저장 시작 → hook 신호와 같은 폴더 동시 작업 경고 → 기기 토큰. 여기가 중단선이다. 수치(방치 시간, 개입 횟수, 사고 건수)를 보고 2차를 정한다. 2차 = 승인 카드(관문 통과 시) → 재시작 내구성 → 데모와 README → 프로토콜 패키지와 server 분해(다음 기능이 실제로 막힐 때).
- 공식 기능 대비 위치 관문: hook 작업 전에 반나절로 한다. 계획 항목마다 "공식이 이미 한다 / 곧 할 것 같다 / 안 할 것"으로 나누고, 실제 작업 몇 건을 공식 Remote Control과 Agent View로도 해 본 뒤 결과를 `devhub-control.md`에 적는다. 앞의 두 부류는 최소 구현이나 공식 기능 위임으로 낮춘다. 승인 카드와 재개 버튼은 이 관문에서 "안 할 것" 또는 "여러 회사 CLI에 필요"로 판정될 때만 착수한다.
- hook 확인 스파이크: 관문과 같은 날 반나절. 수용 목록의 hook 등록 항목에 적은 네 가지를 실제 실행으로 확인하고 결과를 문서에 적는다. 결과가 다르면 승인 카드, 재개 버튼, 상태 전이 항목을 고친 뒤 진행한다.
- 성과 지표: 판단 기록에서 세 가지를 계산해 관제 화면에 분모와 함께 보여 준다. 방치 시간(세션이 입력 대기로 바뀐 뒤 답이 갈 때까지), 하루 개입 횟수, 사고 건수(자율로 보낸 뒤 사람이 되돌리거나 종료한 건, 5분 넘게 놓친 입력 대기). 판단 기록 저장은 CI 직후에 시작해 표본을 쌓는다.
- 무인 장시간 폰 시험(사용자 실행, 리팩터링 전에): 2시간 넘는 작업을 걸어 두고 PC를 떠나 폰만으로 알림 수신, 승인, 결과 확인을 해 본다. 실패 지점을 `devhub-control.md`에 적는다.
- 같은 폴더 동시 작업 경고: 쓰기 가능한 세션(읽기 전용 교차검증 제외)이 이미 도는 폴더나 그 상위, 하위 폴더에 새 세션을 띄우려 하면 경고하고 확인을 받는다. 교차검증은 세션이 끝난 시점의 diff를 파일로 저장해 그 사본을 검토 입력으로 쓴다(이후 다른 세션의 변경이 섞이지 않게). 확인: 겹치는 폴더 판정과 diff 사본 단위 테스트.
- 단일 설계 문서 `docs/designs/devhub-control.md`는 C1 결정과 무관하게 쓴다. 관제 시스템(러너, 슈퍼바이저, 보안, 저장)의 현재 구조와 결정 기록을 담는 문서이고 `devhub.md`(팀 다이제스트)는 그대로 둔다. 이 문서에 공식 Remote Control, Agent View, Dispatch 대비 위치 절을 둔다(가져갈 것 5가지, 더 투자하지 않을 것 1가지). C1이 승인되면 README 첫 화면과 내비게이션 순서만 추가로 바꾼다. 확인: 문서에 해당 절 존재.
- hook 등록: 러너가 Claude Code 대화형 세션을 띄울 때 세션별 설정 파일을 만들어 `claude --settings <파일>`로 넘긴다. 사용자 전역 설정과 프로젝트 `.claude/settings.json`은 건드리지 않는다. hook 명령은 `runner/bin`의 작은 스크립트이고 hook 페이로드를 `POST /runner/hooks`로 보낸다. 이 경로는 루프백 요청만 받고 세션별 비밀값(세션 생성 시 만들어 환경 변수로 넘김)과 `DEVHUB_SESSION`(`runner/src/sessions.ts:130`)으로 세션을 찾는다. 구현 첫 단계에서 공식 hook 문서와 실제 실행으로 네 가지를 확인하고, 다르면 이 항목을 고친 뒤 진행한다: `--settings` 병합 동작, 각 hook의 페이로드 필드, hook이 기다리는 동안 터미널 권한 프롬프트가 뜨는지, hook 자체 시한 설정.
- hook 역할: `Notification`(permission_prompt, idle_prompt)은 입력 대기 상태, `PermissionRequest`는 승인 요청과 그 tool_input, `Stop`은 한 차례 작업 종료. hook이 없는 CLI(Codex, 셸, 사용자 지정, `dclaude` 이전에 열린 창)는 기존 출력 꼬리 판정을 쓴다. 같은 세션에 두 신호가 겹치면 hook이 이기고, hook 신호 뒤 10초 안의 정규식 판정은 무시한다. 확인: hook 페이로드 픽스처로 상태 전이 단위 테스트, 겹침 순서 테스트, hook 없는 세션의 기존 heuristics 테스트 유지.
- 위험 판정: `PermissionRequest`의 tool_input(명령 문자열, 대상 경로)을 위험 패턴 표로 판정한다. 지금 두 벌인 표(`runner/src/supervisor/heuristics.ts:30`의 `DANGER_PATTERNS`, `runner/src/supervisor/chat.ts:28`의 `DANGEROUS_INPUT`)를 `runner/src/danger.ts` 하나로 합치고 세 곳이 같이 쓴다. hook이 없으면 출력 텍스트로 한다. 위험이면 정책과 무관하게 사람 확인. 자율 정책이 스스로 허용하는 것은 허용 목록에 든 요청뿐이다: 읽기 전용 도구, 세션 작업 폴더 안의 파일 편집, 설정 파일에 적은 명령 접두어(기본값: 테스트와 타입 검사 실행). 허용 목록 밖은 위험 패턴에 안 걸려도 사람에게 올린다. 그 외에는 정책에 따른다: 자율이면 허용 목록 안의 요청을 슈퍼바이저가 hook 응답으로 허용하고 actor를 슈퍼바이저로 기록, 제안이면 카드에 제안을 붙여 사람이 누름, 수동이면 카드만. 확인: 위험 명령 tool_input 픽스처 테스트, 정책 3종 분기 테스트.
- 구조화된 승인 카드: `PermissionRequest` hook 스크립트가 러너에 결정을 물으며 최대 90초 기다린다. 카드는 도구, 명령, 대상 파일을 보여 주고 승인 또는 거부를 고르면 hook 응답으로 결정이 돌아간다. 90초 안에 답이 없거나 러너가 응답하지 않으면 hook은 결정 없이 끝나고 Claude Code의 평소 권한 프롬프트가 터미널에 뜬다. 이때 카드는 기존 빠른 입력 버튼으로 바뀐다. 연결된 대시보드 클라이언트가 하나도 없으면 hook은 기다리지 않고 바로 결정 없이 끝난다. hook이 기다리는 동안 터미널 프롬프트가 막힌다는 것이 확인되면 PC에서 연 세션(`dclaude`)에는 카드를 쓰지 않고 기존 방식을 유지한다. PC 터미널에서 먼저 답하면 다음 hook 신호에서 카드를 닫는다. 같은 요청에 두 기기가 답하면 첫 답만 쓰고 둘째는 "이미 처리됨"을 보여 준다. hook이 없는 세션은 기존 빠른 입력 버튼을 유지한다. 노력 M. 확인: 승인, 거부, 시한 초과, 중복 답 단위 테스트.
- 판단 기록: 판단마다 전이, 엔진 응답, 사람이 한 실제 응답(제안 그대로 승인, 고쳐서 전송, 무시, 직접 입력)을 남기고 기존 마스킹 함수로 비밀값을 가린다. `npm run eval:supervisor`는 사람이 실제 응답을 남긴 기록만 골든 세트로 쓰고 두 수치를 낸다. (1) 엔진이 응답을 제안한 건 중 사람이 그대로 승인한 비율, (2) 엔진이 스스로 보내도 된다고 한 건 중 사람 응답과 같은 비율. (2)의 표본은 제안 정책에서 사람이 실제로 답한 기록에서만 온다(자율로 자동 전송된 건은 사람 응답이 없어 제외). 비교는 정규화 후 일치로 한다: 앞뒤 공백 제거, 소문자, `y`와 `yes` 동일, 빈 입력은 Enter, 번호는 숫자. 비교 기준선은 "항상 사람에게 올림"이며 이 기준선은 (2)에서 0건을 처리한다. 분모와 판정 불가 건수를 같이 내고, 표본이 50건 미만이면 비율 대신 "표본 부족"을 낸다. 관제 화면의 슈퍼바이저 영역에 같은 수치와 분모를 보여 준다. 확인: 픽스처 기록으로 평가 스크립트 단위 테스트.
- 저장 모듈: SQLite 이전은 하지 않는다. 새로 저장하는 것(세션 메타, 이벤트, 판단 기록, 기기 목록)만 `runner/src/store/`를 쓰고, 이미 돌아가는 작업 내역과 제품 저장 코드는 손댈 일이 생길 때 옮긴다. `runner/src/store/`가 두 가지를 제공한다. json 문서는 임시 파일에 쓰고 교체하며 Windows에서 교체가 실패하면 3회 재시도한다. jsonl 기록은 한 줄씩 덧붙이고, 읽을 때 깨진 줄(쓰기 중 종료로 잘린 마지막 줄 포함)은 건너뛰며 건수를 로그에 남긴다. 5MB를 넘으면 시작 시점에 이전 파일을 `.1`로 돌린다. 보존: 이벤트와 판단 기록은 회전된 `.1` 하나까지만 둔다. 확인: 깨진 줄, 잘린 마지막 줄, 교체 실패 재시도 단위 테스트.
- 재시작 내구성: 세션 메타(프리셋, cwd, 목표, 정책, 지시, 마지막 200줄, Claude 세션 id)와 슈퍼바이저 이벤트를 저장한다. Claude 세션 id는 hook 페이로드의 `session_id`에서 얻는다. 러너 재시작 후 이전 세션은 "끊긴 세션"으로 보이고, Claude 대화형 프리셋이면서 세션 id가 있으면 `claude --resume <id>` 재개 버튼을 준다. `claude -p`, Codex, 셸, 사용자 지정 세션과 세션 id가 없는 세션은 버튼 대신 이유("이 종류는 이어 붙일 수 없음", "세션 id를 받지 못함")를 보여 준다. 확인: 저장된 메타로 재시작 시나리오 통합 테스트.
- 기기 토큰: 페어링 코드는 관리자 토큰으로 인증된 요청만 만들 수 있고, 8자 무작위, 2분 수명, 1회용이다. 교환 경로(`POST /runner/pair`)는 인증 없이 열리며 기존 실패 잠금(10분 안에 5회 실패하면 15분 잠금, `runner/src/security.ts:21`)과 같은 제한을 받는다. QR 링크 형식은 `#pair=<코드>`이고 터널 QR을 만드는 `runner/src/tunnel.ts:133`과 README를 고친다. 러너 시작 로그의 로컬 대시보드 링크(`runner/src/index.ts:14`)는 로컬 전용 관리자 토큰이라 `#rt=`를 유지한다. 교환하면 기기 토큰을 발급하고 러너는 해시만 저장한다. 기기 토큰은 30일 동안 쓰지 않으면 만료되고 대시보드의 기기 목록(이름, 권한, 마지막 접속)에서 폐기한다. 권한은 두 가지다. "보기와 승인"(세션 보기, 승인 카드와 빠른 입력 버튼 응답, 알림 수신)이 기본이고 안드로이드 알림 서비스는 이것만 쓴다. "전체"(세션 생성, 임의 입력, 종료)는 페어링할 때 PC에서 명시적으로 고른다. 폐기된 기기의 WS는 4001로 닫힌다. 감사 로그에 기기 id를 남긴다. 관리자 토큰만 할 수 있는 일: 페어링 코드 발급, 기기 폐기와 권한 변경, 터널 열기. 터널 닫기는 모든 기기 토큰이 할 수 있다.
- 관리자 토큰: 기존 `runner/.runner-token`은 로컬 전용이다. 터널은 러너의 별도 포트(터널 전용 수신 포트)로만 연결하고, 관리자 토큰은 기본 포트(7331)에서만 통한다. 터널 전용 포트로 온 요청에 관리자 토큰이 오면 401이다. 헤더 유무로 로컬을 판정하지 않는다. 이전 절차: 올린 뒤 터널로 접속하던 폰과 안드로이드 앱은 QR을 한 번 다시 찍는다. 앱은 401을 받으면 저장된 옛 토큰을 지우고 연결 화면을 띄운다. 확인: 만료, 재사용, 폐기, 비활동 만료, 터널 포트의 관리자 토큰 거부, "보기와 승인" 기기의 세션 생성 거부 보안 테스트.
- 쿼리 문자열 토큰 제거: WS는 연결 후 첫 메시지 `hello`(`runner/src/server.ts:441`에 이미 있음)로 인증하고, HTTP도 `?token=`을 받지 않는다(`runner/src/server.ts:70`). 바꿀 곳: `web/lib/runner/settings.ts`, `web/components/control/remote-panel.tsx`(QR 내용), `android/.../Connection.kt`, `android/.../MainActivity.kt`, `runner/bin/devhubctl.mjs`.
- 터널이 열려 있는 동안 관제 화면 상단에 상시 표시하고, 연결된 원격 기기가 하나도 없는 상태가 60분 이어지면 터널을 자동으로 닫는다(시간은 환경 변수로 조정). 안드로이드 알림 서비스나 폰 대시보드의 WS가 붙어 있으면 닫지 않는다(걸어 둔 작업의 알림이 끊기면 안 된다). 실행 중인 세션이 있으면 닫기 전 한 번 더 60분을 준다. 닫히기 5분 전에 연결된 기기에 알리고, 닫히면 안드로이드 알림 서비스는 "터널 닫힘"을 표시한다. 확인: 타이머와 활동 판정 단위 테스트.
- 프로토콜 패키지: 루트 workspaces에 `packages/protocol`을 추가한다. 패키지는 `tsc`로 `dist`를 내고 러너는 빌드 산출물을, web은 `transpilePackages`로 원본을 쓴다. 두 사본 파일은 삭제한다. 루트 `npm test`와 `npm run build`는 프로토콜 패키지 빌드를 먼저 돌린다. 러너식 `.js` 확장자 import가 web의 `transpilePackages`에서 풀리는지 첫 단계에서 확인하고, 안 풀리면 web도 `dist`를 쓴다. 러너 인바운드 메시지(WS, POST 본문)는 zod로 검증하며(web과 같은 주 버전을 러너에 추가) 실패는 오류 응답과 이벤트 로그. 안드로이드는 `android/app/src/test`와 JUnit 의존성을 추가하고, 러너 테스트와 같은 JSON 픽스처 파일을 읽어 알림 파싱을 확인한다. 확인: 잘못된 메시지 거부 테스트, Kotlin 픽스처 테스트.

- worktree 격리는 이번 계획에서 하지 않는다(TODOS). 이유: git 최상위가 30개 넘는 프로젝트가 든 모노레포(`D:Projects`)라 세션마다 저장소 전체를 체크아웃하게 되고, 폴더 이동 커밋 전에는 HEAD에 이 프로젝트가 없다. 부분 체크아웃 설계가 먼저 필요하다.

- P5 처리: 원 계획 P5 중 "상태, 용어 표"와 "빈 상태, 오류 상태, 끊김 상태 화면 정의"는 1차에 한다(아래). "1차 탭 4개로 축소"와 "데스크톱 3단 고정 레이아웃"은 TODOS로 미룬다. 1차 동안 폰 하단 탭은 지금 6개를 유지하고 새 탭을 추가하지 않는다.
- `/control` 첫 화면 순서(폰): 맨 위는 터널이 열려 있을 때만 보이는 한 줄 표시, 그 아래 답 대기열(승인 요청, 입력 대기, 위험 확인을 오래 기다린 순으로, 개수 배지), 그 아래 세션 목록(작업 중, 끊김, 종료 순), 그 아래 관제 AI 대화. 승인 카드는 답 대기열과 해당 세션 상세 두 곳에 뜬다. 기기 목록, 페어링, 지표 화면은 기존 "앱" 칸 아래에 둔다. 데스크톱은 지금 구조를 유지하고 답 대기열만 맨 위에 둔다.
- 상태 표: `docs/designs/devhub-control.md`에 상태 표 한 장을 두고(상태 이름, 발생 조건, 색 토큰, 한 줄 문구, 알림 여부, 주 행동 버튼) `web/components/control/labels.ts`와 안드로이드 문자열이 이 표를 따른다. 새 상태: 승인 요청, 위험 승인 요청, 끊긴 세션, PC에서 처리됨, 이미 처리됨, 시한 지남, 터널 닫힘, 연결 끊김(재시도 중), 다시 연결 필요, 표본 부족. 색은 기존 토큰(`warn`, `danger`, `ok`, `accent`, `muted`)만 쓴다. 문구는 유틸리티 문체이고 이모지를 쓰지 않는다. 확인: 문서에 표 존재, labels 단위 테스트가 표의 상태를 모두 덮음.
- 승인 카드 상태: (1) 누른 뒤 "보내는 중"을 보이고 반영되면 "승인됨" 또는 "거부됨", 실패하면 "전달 실패, 다시 시도"를 보인다. 보내는 중에는 버튼을 막는다. (2) 폰이 다시 붙으면 대기 중인 카드를 러너 시각 기준 남은 시간과 함께 다시 받는다. (3) 여러 세션의 요청은 오래 기다린 순으로 쌓는다. (4) 시한 경계에서 늦게 온 답은 러너가 거절하고 카드를 "시한 지남" 모양으로 바꾼다. (5) 긴 명령은 3줄에서 줄이고 눌러 펼친다. 대상 파일이 여럿이면 처음 3개와 "외 N개". (6) 슈퍼바이저가 허용 목록으로 자동 허용한 건은 카드 없이 피드 한 줄(actor 슈퍼바이저)로 남긴다. (7) PC에서 먼저 답하면 카드는 "PC에서 처리됨"으로 닫힌다. 확인: 상태별 컴포넌트 테스트.
- 시한 뒤의 카드: 시한이 지나도 카드의 도구, 명령, 대상 파일은 그대로 남는다. 응답 수단만 "터미널에 키 전송"으로 바뀌고 카드에 "시간이 지나 터미널 프롬프트로 넘어갔습니다. 아래 버튼은 터미널에 입력을 보냅니다" 한 줄이 붙는다. 시한 길이는 90초 고정이 아니라 설정값이고, hook 확인 스파이크에서 hook 자체 시한을 확인한 뒤 허용되는 가장 긴 값으로 기본값을 정한다(CEO 수용 목록의 "최대 90초"는 이 항목으로 대체).
- "연결된 대시보드 클라이언트"의 정의: 폰과 PC의 대시보드 WS와 안드로이드 알림 서비스 WS를 모두 포함한다. 알림 서비스만 붙어 있어도 hook은 기다리고, 승인 요청은 알림으로 간다.
- 위험 승인: 위험 카드는 `danger` 색과 "위험: <걸린 패턴 이름>" 문구로 구분한다. 알림에는 승인 버튼을 두지 않고 "거부"와 "열기"만 둔다. 카드 안에서는 승인을 누른 뒤 "정말 실행" 확인을 한 번 더 받는다. 일반 카드는 한 번 누름을 유지한다. "보기와 승인" 기기도 이 두 단계로 위험 승인을 할 수 있다(취향 결정).
- 잘못된 판단 표시: 피드의 슈퍼바이저 자동 응답 줄에 "잘못된 판단" 표시 버튼을 둔다. 사고 건수는 이 표시와 "5분 넘게 놓친 입력 대기"만 센다(CEO 수용 목록의 "되돌리거나 종료한 건"을 대체). 지표에는 기간(오늘, 7일)과 기록 시작일을 같이 보여 준다.
- 지표 위치: 첫 화면에는 방치 시간 한 줄만 둔다. 개입 횟수, 사고 건수, 평가 비율 2종은 "앱" 칸 아래 지표 화면에 둔다. 표본이 부족하면 "50건 중 N건"으로 진행을 보여 준다. 지표는 신호 출처(hook 확정, 출력 추정)별로 나눠 보여 준다.
- 신호 출처 표시: 세션 카드의 상태 옆에 "확정"(hook) 또는 "추정"(출력 판정)을 작은 배지로 둔다.
- 페어링: 연결 화면에 QR 스캔과 함께 8자 코드 직접 입력 칸을 둔다. 코드 문자 집합에서 0, O, 1, I, l을 뺀다. 안드로이드 앱은 앱 안 스캐너로 받는다(지금 연결 방식과 같음). PC 쪽 순서: 권한 선택(기본 "보기와 승인"이 강조됨) → QR과 코드 표시 → 2분 카운트다운 → 만료 시 "다시 만들기". 기기 이름은 폰에서 입력하고 기본값은 기기 종류다. 폰 쪽 문구 네 가지: "코드가 만료되었습니다", "이미 사용된 코드입니다", "시도가 많아 잠겼습니다. N분 뒤 다시"(남은 시간 표시), "연결되었습니다". 기기 목록에는 "이 기기" 표시, 만료까지 7일 이하면 표시, 폐기 전 확인. 실기기 체크리스트의 재페어링은 브라우저, 홈 화면 PWA, 안드로이드 앱 세 경로로 나눈다.
- 연결 상태 문구: 연결 화면은 사유별 한 줄을 보여 준다. 옛 토큰(401)은 "보안 방식이 바뀌어 다시 연결이 필요합니다", 폐기(4001)는 "PC에서 이 기기가 해제되었습니다", 비활동 만료는 "30일 동안 쓰지 않아 만료되었습니다", 인증 전 구간은 "연결 중". 러너가 터널을 닫기 직전 WS로 사유 코드를 보내면 "터널 닫힘, PC에서 다시 열고 QR을 다시 찍으세요", 사유 없이 끊기면 "연결 끊김, 다시 시도 중"이다.
- 터널 닫힘 예고(CEO 수용 목록의 "닫히기 5분 전에 연결된 기기에 알리고"를 대체): 자동 닫힘 조건이 "연결된 기기 없음"이라 알릴 기기가 없다. 예고는 PC 대시보드에만 띄운다. 터널 주소가 다시 열 때 바뀌는 구성(ngrok 무료)임을 `devhub-control.md`에 적는다.
- 폰에서 터널 닫기: 원격 기기에서 닫을 때 "이 기기도 끊기며 PC에서만 다시 열 수 있습니다. 실행 중 세션 N개" 확인을 받는다. 상단 터널 표시의 닫기 버튼은 한 번 눌러 펼친 뒤에만 보인다.
- 끊긴 세션: 재개하면 같은 카드에서 상태만 바뀐다. 재개 실패(작업 폴더 없음, 세션 id 무효)는 카드에 사유를 보여 준다. 저장된 마지막 200줄은 읽기 전용으로 볼 수 있다. 개별 닫기가 있고 7일 뒤 자동 정리한다.
- 같은 폴더 경고: 어느 세션과 겹치는지와 관계(같은 폴더, 상위, 하위)를 보여 주고 선택지는 "기존 세션 열기", "그래도 시작", "취소" 셋이다. 관제 AI가 세션을 만들 때 겹치면 AI가 만들지 않고 사람에게 확인 카드를 올린다.
- "보기와 승인" 기기의 화면: 새 작업, 임의 입력, 종료는 숨기지 않고 비활성으로 두고 "이 기기는 보기와 승인 권한입니다" 한 줄을 붙인다. 관제 AI 대화 입력도 비활성이다(대화가 세션을 만들 수 있으므로).
- 빈 상태와 데모: 세션이 0개인 첫 실행은 "아직 세션이 없습니다"와 다음 행동 하나("새 작업")를 보여 준다. `npm run demo`의 가짜 세션은 작업 중, 구조화된 승인 카드가 뜬 입력 대기, 오류, 끊긴 세션 네 개이고 터널 표시도 켠다(CEO 수용 목록의 "가짜 세션 3개"를 대체). 화면에 "데모" 표시를 상시 둔다.
- 접근성과 반응형: 폰의 승인, 거부 버튼은 높이 44px 이상. 위험과 일반의 구분은 색과 문구 둘 다로 한다. 승인 카드는 키보드로 포커스 이동이 되고 Enter는 승인(위험 카드는 확인 단계로), Esc는 닫기. 답 대기열은 `aria-live="polite"`. 360px 폭에서 카드의 명령 줄은 가로 스크롤이 아니라 줄바꿈.
- hook 확인 스파이크와 무인 폰 시험의 확인 항목에 추가: hook 자체 시한의 최대값, 알림을 보고 앱을 열어 승인하기까지 실제 걸린 시간, 설치된 PWA와 앱에서 페어링이 끝나는지.

- 계획 문서 정리: 구현을 시작하기 전에 이 계획을 대체 관계가 모두 반영된 단일 본문으로 다시 쓴다(원 본문, CEO 수용 목록, 디자인 수용 목록, 이 목록의 "…를 대체" 문장을 풀어 한 벌로). 대체 이력은 결정 기록에 남긴다.
- 순서(CEO 수용 목록의 순서를 대체): 1차 = 폴더 이동 커밋(사용자 승인) → CI와 실패 테스트 → 데모와 `npm run dev` 수정, README 첫 화면 → 터널 표시와 자동 닫힘 → 무인 장시간 폰 시험(지금 인증 방식 그대로, 사용자) → 공식 기능 관문과 hook 스파이크 → 오류 규약과 판단 기록 저장 → 인증 전환(페어링, 기기 토큰, 쿼리 토큰 제거, 터널 전용 포트, 프로토콜 버전, 새 APK를 한 번에) → hook 신호와 같은 폴더 경고. 여기가 중단선. 2차 = 승인 카드(데모의 가짜 카드를 실물로) → 재시작 내구성 → 프로토콜 패키지와 server 분해(필요할 때).
- 인증 전환은 한 번에: 터널 포트에서 관리자 토큰을 거부하는 변경은 기기 토큰과 페어링이 동작하는 같은 릴리스에서만 켠다. 그 전 단계에서는 원격 접속 방식을 바꾸지 않는다. 호환 표(러너 버전, 웹, 안드로이드 APK, devhubctl, `devhub-runner` 스킬)와 "올린 뒤 할 일"(QR 다시 스캔, 새 APK 설치, devhubctl은 로컬 전용)을 `docs/runbook.md`와 CHANGELOG에 적는다. 전환 한 릴리스 전부터 대시보드에 "다음 버전에서 다시 연결이 필요합니다"를 띄운다.
- 프로토콜 버전: `hello`에 정수 `protocol`을 넣는다. 러너는 낮은 버전을 "앱 업데이트 필요" 사유 코드로 닫고, 높은 버전은 "러너 업데이트 필요"로 닫는다. 공용 픽스처에 버전 불일치 사례를 넣는다.
- 오류 규약: 러너의 HTTP 오류 본문은 기존 `error` 문자열을 유지하고 필드를 추가한다: `code`(영어 고정 식별자), `fix`(고칠 방법 한 줄), `retry`(`no`, `after_ms`, `after_fix`), 필요하면 `retryAfterMs`, 예기치 못한 실패에는 `traceId`. 예기치 못한 실패는 400이 아니라 500이고 원문 메시지는 마스킹해 로그에만 남긴다. WS 오류 메시지도 같은 필드를 가진다. 사람용 한국어 문구는 `labels.ts`에서 `code`로 변환한다. 코드 목록과 고칠 방법은 `docs/errors.md`에 코드별 앵커로 둔다. 확인: 코드 목록의 모든 코드가 문서에 있는지 검사하는 테스트.
- 새 오류의 코드: 인증은 `token_legacy`, `admin_on_tunnel`, `device_expired`, `device_revoked`, `locked_out`. 페어링은 `pair_expired`, `pair_used`. 권한은 `scope_denied`(fix: PC에서 이 기기 권한 변경). 검증은 `invalid_message`(필드 경로와 기대 타입 포함, 받은 본문은 마스킹해 로그에). hook은 `hook_unknown_session`, `hook_bad_secret`, `hook_duplicate`(같은 요청 id는 한 번만 처리). 저장은 `store_write_failed`. 터널은 `tunnel_port_in_use`. 재개는 `resume_no_cwd`(fix: 같은 지시로 새 세션), `resume_bad_id`(fix: 마지막 200줄을 붙여 새 세션).
- WS 닫힘 코드(디자인 수용 목록의 "폐기(4001)"를 대체): 4001 인증 실패(지금 뜻 유지), 4003 기기 폐기, 4004 비활동 만료, 4005 터널 닫힘, 4006 프로토콜 버전 불일치, 4029 잠금(지금 뜻 유지). 상태 표에 넣는다.
- 저장 실패는 조용히 넘기지 않는다: 교체가 3회 실패하면 호출자에게 오류를 올린다. 기기 폐기와 권한 변경은 저장에 실패하면 실패로 응답하고 메모리 상태도 바꾸지 않는다. 판단 기록 쓰기 실패는 이벤트 로그에 파일 경로와 OS 오류 코드를 남기고 관제 화면에 한 번 보여 준다.
- hook 스크립트의 실패 규약: 러너가 응답하지 않거나 시한이 지나면 종료 코드 0과 빈 출력으로 끝난다(결정 없음). 원인은 `runner/.data/hook-errors.log`에 한 줄 남긴다. 비밀값은 어디에도 출력하지 않는다. 세션별 hook 비밀값은 기존 마스킹 함수에 등록해 터미널 꼬리, 저장되는 마지막 200줄, 판단 엔진 프롬프트에서 가린다. `/runner/hooks`로 들어온 신호만으로는 승인 결정을 바꿀 수 없다(결정은 인증된 기기의 응답으로만). 스파이크 확인 항목에 hook 종료 코드와 stderr의 해석을 추가한다.
- hook 끄기: 세션 생성 옵션과 환경 변수(`RUNNER_HOOKS=0`)로 hook 주입을 끌 수 있고, 끄면 출력 꼬리 판정으로 돌아가며 배지는 "추정"이다.
- 세션 종류의 표현: 프리셋 이름으로 Claude 대화형 세션을 추정하지 않는다. 세션 메타에 `agent`(`claude`, `codex`, `shell`, `custom`)와 `interactive`(참, 거짓)를 명시한다. `dclaude`와 `devhubctl claude`(지금은 `preset: "custom"`으로 만든다, `runner/bin/devhubctl.mjs:160`)도 `agent: claude`로 표시해 hook과 재개 대상이 된다. 사용자가 직접 `--settings`를 넘긴 경우는 hook을 주입하지 않고 "추정"으로 둔다. 스파이크에서 `dclaude` 경로를 직접 확인한다.
- 승인 재전송: 요청 id별로 첫 답만 쓴다. 같은 기기가 같은 답을 다시 보내면 성공으로 돌려준다("이미 처리됨"은 다른 기기나 다른 답일 때만).
- devhubctl: `--help`와 하위 명령별 사용법을 전용 처리한다. `--json`이면 stdout에는 JSON만, 진행 문구는 stderr. 실패는 0이 아닌 종료 코드(`tunnel start`의 오류와 시간 초과 포함). 기다리는 명령(`review --wait`, `tunnel start`)에 `--timeout`을 두고 기본값을 문서에 적는다. 오류는 stderr에 `code`와 `fix`를 포함해 출력한다. devhubctl은 로컬 전용이고 원격 주소가 주어지면 요청 전에 거절한다. `devhub-runner` 스킬 문서를 같은 커밋에서 고친다.
- 러너 시작 로그(취향 결정): 로그에는 대시보드 주소만 찍고 관리자 토큰이 든 링크는 찍지 않는다. `devhubctl open`이 토큰이 든 로컬 주소를 브라우저로 연다. 이유: 러너를 DevHub 세션 안에서 띄우면 로그의 토큰이 터미널 꼬리로 폰에 전달된다.
- 데모(디자인 수용 목록의 데모 항목에 추가): `npm run demo`는 가짜 SessionManager로 node-pty를 import하지 않고, 루프백 전용, 토큰 없이 뜬다. 시작 로그 마지막 줄에 주소 하나를 찍고 브라우저를 연다. 포트가 쓰이고 있으면 다음 포트를 쓴다. Ctrl+C로 끝난다. 1차에서는 가짜 승인 카드와 가짜 끊긴 세션을 화면 모양으로만 보여 주고 2차에서 실물과 연결한다. 실패하면 원인과 고칠 방법(예: Node 버전)을 한 줄로 낸다. 확인: CI에서 데모를 띄워 `/control`이 200을 주는지 본다.
- 개발 실행: 루트 `npm run dev`의 `&`를 Windows에서도 두 프로세스를 같이 띄우는 node 스크립트로 바꾼다(새 의존성 없이). Node 버전을 `engines`와 `.nvmrc`로 고정한다. CI는 `windows-latest`에서 러너 테스트를 돌리고 `ubuntu-latest`에서 나머지를 돌린다. 안드로이드 픽스처 테스트는 CI에서 gradle 단위 테스트로 돌린다(인증 전환 단계부터).
- 문서 나눔(CEO 수용 목록의 "단일 설계 문서"를 보완): `docs/designs/devhub-control.md`는 구조, 상태 표, 결정 기록, 공식 기능 대비 위치, 대안 비교만 담는다. `docs/errors.md`는 오류 코드, `docs/runbook.md`는 페어링, 터널, 올린 뒤 할 일, 실기기 체크리스트와 결과, 스파이크와 무인 시험 결과를 담는다. README는 첫 화면에 세 단계를 둔다: 데모(아무것도 필요 없음), 로컬(Claude Code 필요), 원격(ngrok 또는 cloudflared 필요). 각 단계의 명령은 작업 폴더를 명시하고 PowerShell과 POSIX 셸 둘 다에서 그대로 실행되는 형태로 적는다. devhubctl 예시 세 개(세션 목록, 생성, 출력 읽기)를 둔다.
- 설정 표: 새 설정의 이름을 `RUNNER_` 접두어로 통일하고 표(이름, 기본값, 허용 범위)를 `devhub-control.md`에 둔다: 터널 전용 포트(`RUNNER_TUNNEL_PORT`), 자동 닫힘 분(`RUNNER_TUNNEL_IDLE_MIN`, 0은 닫지 않음이고 상단 표시에 "자동 닫힘 꺼짐"), 승인 시한, 기기 토큰 비활동 일수, 끊긴 세션 정리 일수, 회전 크기, hook 켜기. 자율 허용 명령 접두어는 `runner/.data/allow.json`에 둔다. 보안 값(잠금 횟수, 페어링 수명)은 조정할 수 없다.
- `npm run eval:supervisor`의 종료 코드: 표본 부족은 0과 명시적 상태, 기록 파일 없음이나 파싱 불가는 0이 아닌 코드. `--json` 출력을 제공한다.
- 권한 식별자: 프로토콜과 감사 로그에는 `approve`와 `full`을 쓰고 화면 문구("보기와 승인", "전체")는 `labels.ts`에만 둔다.
- 시작 경험 측정: 데모와 README를 고친 뒤 깨끗한 폴더에서 README만 보고 데모를 띄우는 시간을 한 번 재서 `docs/runbook.md`에 적는다(사람이 잰 값, 날짜, 환경).

- 지금 열려 있는 문제부터(순서 조정, DX 수용 목록의 순서에 끼워 넣음): CI 직후, 무인 폰 시험 전에 세 가지를 한다. (1) 터널 전용 리스너와 프록시 허용 경로, (2) 잠금 키 수정, (3) `.gitignore`에 `*.keystore`, `*.jks`, `*.apk` 추가. 이 셋은 원격 접속 방식을 바꾸지 않는다(관리자 토큰 거부는 인증 전환 때 켠다). 그 뒤 순서는 DX 수용 목록대로이며, 인증 전환 안에서 "인증 한 겹"을 가장 먼저 만든다.
- 터널 전용 리스너: 러너는 리스너 두 개를 연다. 기본 리스너(7331)와 터널 리스너(`RUNNER_TUNNEL_PORT`). 터널 프로세스는 터널 리스너에만 붙는다. 요청이 어느 리스너로 들어왔는지를 인증, 프록시, WS 업그레이드, 잠금 키 산정까지 전달한다. "루프백인가"가 아니라 "어느 리스너인가"로 판정한다(CEO 수용 목록의 "루프백 요청만"을 대체). 터널 리스너에서는 `/runner/hooks`, 페어링 코드 발급, 기기 관리, 터널 열기를 경로 단계에서 404로 막는다.
- 터널 프록시 허용 경로: 터널 리스너는 Next로 가는 경로 중 `/control`, 그 정적 자산(`/_next/*`), `manifest`, 서비스 워커, 아이콘만 통과시키고 나머지(`/teams`, `/api/*`, `/join/*`, `/compile`, `/console`, `/products` 포함)는 404다. WS 업그레이드도 같은 규칙을 따른다(`/runner/ws`만). 확인: 터널 리스너로 `/api/auth/dev`, `/teams`, 허용 밖 WS 업그레이드가 404인지.
- 잠금 키: 기본 리스너에서는 X-Forwarded-For를 무시하고 소켓 주소만 쓴다. 터널 리스너에서는 터널 사업자가 붙인 값(X-Forwarded-For의 마지막 항목, cloudflared는 `CF-Connecting-IP`)만 쓴다. 페어링 교환에는 클라이언트와 무관한 한도를 둔다: 유효한 코드가 있는 동안 실패가 누적 10회면 그 코드를 폐기한다. 유효한 코드가 없으면 교환 경로는 바로 거절한다. 같은 코드의 동시 교환은 한 번만 성공한다. 확인: 헤더를 바꿔 가며 시도해도 코드가 폐기되는지, 동시 교환 테스트.
- 인증 한 겹: `authenticate(req, listener)`가 `Principal{kind: admin|device, scope, deviceId}`를 돌려주는 함수 하나로 인증을 모은다. 모든 HTTP 경로와 WS 메시지 종류에 필요한 권한(`public`, `approve`, `full`, `admin`)을 선언한 표를 두고, 선언이 없으면 거부한다. `approve` 권한이 할 수 있는 것은 세션 보기, 러너가 보관한 승인 요청과 선택지에 대한 응답, 알림 수신, 터널 닫기뿐이다. 컴파일 실행, 관제 AI, 정책과 목표 변경, 교차검증 시작, 요약 호출, 제품과 난제 쓰기, 폴더 탐색은 `full` 이상이다. `approve` 기기의 빠른 입력은 임의 문자열이 아니라 러너가 그 요청에 대해 보관한 선택지 중 하나만 받는다. 확인: 경로와 메시지 종류를 전수 열거해 `approve` 토큰으로 호출하고 표와 대조하는 테스트, 선언 없는 경로가 추가되면 실패하는 테스트.
- 단일 결정 경로: 세션마다 승인과 입력 대기를 요청 id와 revision으로 관리하는 대기열 하나(`runner/src/decisions.ts`)를 둔다. hook 신호, 출력 판정, AI 판단, 사람 응답, 관제 AI의 입력이 모두 이 경로로 들어오고, PTY에 입력을 쓰는 곳은 여기 한 곳이다. 어떤 입력이든 들어가면 그 세션의 revision이 오르고, 낮은 revision을 들고 온 답(늦게 돌아온 AI 판단 포함)은 거절한다. CEO 수용 목록의 "hook 신호 뒤 10초 안의 정규식 판정은 무시"는 이 규칙으로 대체한다. 확인: 늦은 AI 판단 거절, 한 세션의 동시 요청 두 건, 두 기기 동시 응답 테스트.
- 결정 전달 상태: 승인 요청은 대기, 결정됨, hook에 전달됨, 전달 불명, 시한 지남(터미널로 넘어감) 다섯 상태를 가진다. hook 연결이 끊기면 전달 불명으로 두고 카드에 "반영 여부를 확인하세요"와 세션 열기를 보인다. 같은 요청 id의 재시도는 같은 결정을 돌려준다. 러너가 승인 대기 중 재시작하면 hook은 결정 없음으로 끝나고 재시작한 러너는 그 요청을 남기지 않는다.

- hook 역할: `Notification`(permission_prompt, idle_prompt)은 입력 대기 상태, `PermissionRequest`는 승인 요청과 그 tool_input, `Stop`은 한 차례 작업 종료. hook이 없는 CLI(Codex, 셸, 사용자 지정, `dclaude` 이전에 열린 창)는 기존 출력 꼬리 판정을 쓴다. 같은 세션에 두 신호가 겹치면 hook이 이기고, hook 신호 뒤 10초 안의 정규식 판정은 무시한다. 확인: hook 페이로드 픽스처로 상태 전이 단위 테스트, 겹침 순서 테스트, hook 없는 세션의 기존 heuristics 테스트 유지.
- 위험 판정: `PermissionRequest`의 tool_input(명령 문자열, 대상 경로)을 위험 패턴 표로 판정한다. 지금 두 벌인 표(`runner/src/supervisor/heuristics.ts:30`의 `DANGER_PATTERNS`, `runner/src/supervisor/chat.ts:28`의 `DANGEROUS_INPUT`)를 `runner/src/danger.ts` 하나로 합치고 세 곳이 같이 쓴다. hook이 없으면 출력 텍스트로 한다. 위험이면 정책과 무관하게 사람 확인. 자율 정책이 스스로 허용하는 것은 허용 목록에 든 요청뿐이다: 읽기 전용 도구, 세션 작업 폴더 안의 파일 편집, 설정 파일에 적은 명령 접두어(기본값: 테스트와 타입 검사 실행). 허용 목록 밖은 위험 패턴에 안 걸려도 사람에게 올린다. 그 외에는 정책에 따른다: 자율이면 허용 목록 안의 요청을 슈퍼바이저가 hook 응답으로 허용하고 actor를 슈퍼바이저로 기록, 제안이면 카드에 제안을 붙여 사람이 누름, 수동이면 카드만. 확인: 위험 명령 tool_input 픽스처 테스트, 정책 3종 분기 테스트.
- 구조화된 승인 카드: `PermissionRequest` hook 스크립트가 러너에 결정을 물으며 최대 90초 기다린다. 카드는 도구, 명령, 대상 파일을 보여 주고 승인 또는 거부를 고르면 hook 응답으로 결정이 돌아간다. 90초 안에 답이 없거나 러너가 응답하지 않으면 hook은 결정 없이 끝나고 Claude Code의 평소 권한 프롬프트가 터미널에 뜬다. 이때 카드는 기존 빠른 입력 버튼으로 바뀐다. 연결된 대시보드 클라이언트가 하나도 없으면 hook은 기다리지 않고 바로 결정 없이 끝난다. hook이 기다리는 동안 터미널 프롬프트가 막힌다는 것이 확인되면 PC에서 연 세션(`dclaude`)에는 카드를 쓰지 않고 기존 방식을 유지한다. PC 터미널에서 먼저 답하면 다음 hook 신호에서 카드를 닫는다. 같은 요청에 두 기기가 답하면 첫 답만 쓰고 둘째는 "이미 처리됨"을 보여 준다. hook이 없는 세션은 기존 빠른 입력 버튼을 유지한다. 노력 M. 확인: 승인, 거부, 시한 초과, 중복 답 단위 테스트.
- 판단 기록: 판단마다 전이, 엔진 응답, 사람이 한 실제 응답(제안 그대로 승인, 고쳐서 전송, 무시, 직접 입력)을 남기고 기존 마스킹 함수로 비밀값을 가린다. `npm run eval:supervisor`는 사람이 실제 응답을 남긴 기록만 골든 세트로 쓰고 두 수치를 낸다. (1) 엔진이 응답을 제안한 건 중 사람이 그대로 승인한 비율, (2) 엔진이 스스로 보내도 된다고 한 건 중 사람 응답과 같은 비율. (2)의 표본은 제안 정책에서 사람이 실제로 답한 기록에서만 온다(자율로 자동 전송된 건은 사람 응답이 없어 제외). 비교는 정규화 후 일치로 한다: 앞뒤 공백 제거, 소문자, `y`와 `yes` 동일, 빈 입력은 Enter, 번호는 숫자. 비교 기준선은 "항상 사람에게 올림"이며 이 기준선은 (2)에서 0건을 처리한다. 분모와 판정 불가 건수를 같이 내고, 표본이 50건 미만이면 비율 대신 "표본 부족"을 낸다. 관제 화면의 슈퍼바이저 영역에 같은 수치와 분모를 보여 준다. 확인: 픽스처 기록으로 평가 스크립트 단위 테스트.
- 저장 모듈: SQLite 이전은 하지 않는다. 새로 저장하는 것(세션 메타, 이벤트, 판단 기록, 기기 목록)만 `runner/src/store/`를 쓰고, 이미 돌아가는 작업 내역과 제품 저장 코드는 손댈 일이 생길 때 옮긴다. `runner/src/store/`가 두 가지를 제공한다. json 문서는 임시 파일에 쓰고 교체하며 Windows에서 교체가 실패하면 3회 재시도한다. jsonl 기록은 한 줄씩 덧붙이고, 읽을 때 깨진 줄(쓰기 중 종료로 잘린 마지막 줄 포함)은 건너뛰며 건수를 로그에 남긴다. 5MB를 넘으면 시작 시점에 이전 파일을 `.1`로 돌린다. 보존: 이벤트와 판단 기록은 회전된 `.1` 하나까지만 둔다. 확인: 깨진 줄, 잘린 마지막 줄, 교체 실패 재시도 단위 테스트.
- 재시작 내구성: 세션 메타(프리셋, cwd, 목표, 정책, 지시, 마지막 200줄, Claude 세션 id)와 슈퍼바이저 이벤트를 저장한다. Claude 세션 id는 hook 페이로드의 `session_id`에서 얻는다. 러너 재시작 후 이전 세션은 "끊긴 세션"으로 보이고, Claude 대화형 프리셋이면서 세션 id가 있으면 `claude --resume <id>` 재개 버튼을 준다. `claude -p`, Codex, 셸, 사용자 지정 세션과 세션 id가 없는 세션은 버튼 대신 이유("이 종류는 이어 붙일 수 없음", "세션 id를 받지 못함")를 보여 준다. 확인: 저장된 메타로 재시작 시나리오 통합 테스트.
- 기기 토큰: 페어링 코드는 관리자 토큰으로 인증된 요청만 만들 수 있고, 8자 무작위, 2분 수명, 1회용이다. 교환 경로(`POST /runner/pair`)는 인증 없이 열리며 기존 실패 잠금(10분 안에 5회 실패하면 15분 잠금, `runner/src/security.ts:21`)과 같은 제한을 받는다. QR 링크 형식은 `#pair=<코드>`이고 터널 QR을 만드는 `runner/src/tunnel.ts:133`과 README를 고친다. 러너 시작 로그의 로컬 대시보드 링크(`runner/src/index.ts:14`)는 로컬 전용 관리자 토큰이라 `#rt=`를 유지한다. 교환하면 기기 토큰을 발급하고 러너는 해시만 저장한다. 기기 토큰은 30일 동안 쓰지 않으면 만료되고 대시보드의 기기 목록(이름, 권한, 마지막 접속)에서 폐기한다. 권한은 두 가지다. "보기와 승인"(세션 보기, 승인 카드와 빠른 입력 버튼 응답, 알림 수신)이 기본이고 안드로이드 알림 서비스는 이것만 쓴다. "전체"(세션 생성, 임의 입력, 종료)는 페어링할 때 PC에서 명시적으로 고른다. 폐기된 기기의 WS는 4001로 닫힌다. 감사 로그에 기기 id를 남긴다. 관리자 토큰만 할 수 있는 일: 페어링 코드 발급, 기기 폐기와 권한 변경, 터널 열기. 터널 닫기는 모든 기기 토큰이 할 수 있다.
- 관리자 토큰: 기존 `runner/.runner-token`은 로컬 전용이다. 터널은 러너의 별도 포트(터널 전용 수신 포트)로만 연결하고, 관리자 토큰은 기본 포트(7331)에서만 통한다. 터널 전용 포트로 온 요청에 관리자 토큰이 오면 401이다. 헤더 유무로 로컬을 판정하지 않는다. 이전 절차: 올린 뒤 터널로 접속하던 폰과 안드로이드 앱은 QR을 한 번 다시 찍는다. 앱은 401을 받으면 저장된 옛 토큰을 지우고 연결 화면을 띄운다. 확인: 만료, 재사용, 폐기, 비활동 만료, 터널 포트의 관리자 토큰 거부, "보기와 승인" 기기의 세션 생성 거부 보안 테스트.
- 쿼리 문자열 토큰 제거: WS는 연결 후 첫 메시지 `hello`(`runner/src/server.ts:441`에 이미 있음)로 인증하고, HTTP도 `?token=`을 받지 않는다(`runner/src/server.ts:70`). 바꿀 곳: `web/lib/runner/settings.ts`, `web/components/control/remote-panel.tsx`(QR 내용), `android/.../Connection.kt`, `android/.../MainActivity.kt`, `runner/bin/devhubctl.mjs`.
- 터널이 열려 있는 동안 관제 화면 상단에 상시 표시하고, 연결된 원격 기기가 하나도 없는 상태가 60분 이어지면 터널을 자동으로 닫는다(시간은 환경 변수로 조정). 안드로이드 알림 서비스나 폰 대시보드의 WS가 붙어 있으면 닫지 않는다(걸어 둔 작업의 알림이 끊기면 안 된다). 실행 중인 세션이 있으면 닫기 전 한 번 더 60분을 준다. 닫히기 5분 전에 연결된 기기에 알리고, 닫히면 안드로이드 알림 서비스는 "터널 닫힘"을 표시한다. 확인: 타이머와 활동 판정 단위 테스트.
- 프로토콜 패키지: 루트 workspaces에 `packages/protocol`을 추가한다. 패키지는 `tsc`로 `dist`를 내고 러너는 빌드 산출물을, web은 `transpilePackages`로 원본을 쓴다. 두 사본 파일은 삭제한다. 루트 `npm test`와 `npm run build`는 프로토콜 패키지 빌드를 먼저 돌린다. 러너식 `.js` 확장자 import가 web의 `transpilePackages`에서 풀리는지 첫 단계에서 확인하고, 안 풀리면 web도 `dist`를 쓴다. 러너 인바운드 메시지(WS, POST 본문)는 zod로 검증하며(web과 같은 주 버전을 러너에 추가) 실패는 오류 응답과 이벤트 로그. 안드로이드는 `android/app/src/test`와 JUnit 의존성을 추가하고, 러너 테스트와 같은 JSON 픽스처 파일을 읽어 알림 파싱을 확인한다. 확인: 잘못된 메시지 거부 테스트, Kotlin 픽스처 테스트.
- `server.ts`를 기능 모듈 등록 방식으로 나누되 `/runner/*` 경로와 응답 모양은 바꾸지 않는다. 확인: 기존 server, security 테스트에서 인증 방식(쿼리 토큰)에 관한 단언만 고치고 나머지는 수정 없이 통과.
- worktree 격리는 이번 계획에서 하지 않는다(TODOS). 이유: git 최상위가 30개 넘는 프로젝트가 든 모노레포(`D:Projects`)라 세션마다 저장소 전체를 체크아웃하게 되고, 폴더 이동 커밋 전에는 HEAD에 이 프로젝트가 없다. 부분 체크아웃 설계가 먼저 필요하다.
- `npm run demo`는 API 키와 Claude 없이 가짜 세션 3개(작업 중, 입력 대기, 오류)로 관제 화면을 띄운다. README 첫 화면은 이 경로와 스크린샷이다.

- 실기기 체크리스트(폰 PWA 설치, 안드로이드 APK 설치, 알림 버튼, 360px 레이아웃, QR 재페어링)를 `docs/designs/devhub-control.md`에 두고 한 번 돌려 결과를 기록한다. 실행은 사용자 몫이다.

**Section 9 배포.** 배포 대상은 이 PC의 러너와 폰의 앱뿐이다. 기기 토큰 전환이 유일한 호환 단절이고(폰과 앱 QR 재페어링) 수용 목록에 절차가 있다. 안드로이드 앱은 새 APK 설치가 필요하다. 위험 2건: 옛 앱이 `#rt=` 링크를 강제(`MainActivity.kt:134`)하므로 러너와 앱을 같이 올려야 함, CI는 폴더 이동 커밋 뒤에만 돈다.

- "연결된 대시보드 클라이언트"의 정의: 폰과 PC의 대시보드 WS와 안드로이드 알림 서비스 WS를 모두 포함한다. 알림 서비스만 붙어 있어도 hook은 기다리고, 승인 요청은 알림으로 간다.
- 위험 승인: 위험 카드는 `danger` 색과 "위험: <걸린 패턴 이름>" 문구로 구분한다. 알림에는 승인 버튼을 두지 않고 "거부"와 "열기"만 둔다. 카드 안에서는 승인을 누른 뒤 "정말 실행" 확인을 한 번 더 받는다. 일반 카드는 한 번 누름을 유지한다. "보기와 승인" 기기도 이 두 단계로 위험 승인을 할 수 있다(취향 결정).
- 잘못된 판단 표시: 피드의 슈퍼바이저 자동 응답 줄에 "잘못된 판단" 표시 버튼을 둔다. 사고 건수는 이 표시와 "5분 넘게 놓친 입력 대기"만 센다(CEO 수용 목록의 "되돌리거나 종료한 건"을 대체). 지표에는 기간(오늘, 7일)과 기록 시작일을 같이 보여 준다.
- 지표 위치: 첫 화면에는 방치 시간 한 줄만 둔다. 개입 횟수, 사고 건수, 평가 비율 2종은 "앱" 칸 아래 지표 화면에 둔다. 표본이 부족하면 "50건 중 N건"으로 진행을 보여 준다. 지표는 신호 출처(hook 확정, 출력 추정)별로 나눠 보여 준다.
- 신호 출처 표시: 세션 카드의 상태 옆에 "확정"(hook) 또는 "추정"(출력 판정)을 작은 배지로 둔다.
- 페어링: 연결 화면에 QR 스캔과 함께 8자 코드 직접 입력 칸을 둔다. 코드 문자 집합에서 0, O, 1, I, l을 뺀다. 안드로이드 앱은 앱 안 스캐너로 받는다(지금 연결 방식과 같음). PC 쪽 순서: 권한 선택(기본 "보기와 승인"이 강조됨) → QR과 코드 표시 → 2분 카운트다운 → 만료 시 "다시 만들기". 기기 이름은 폰에서 입력하고 기본값은 기기 종류다. 폰 쪽 문구 네 가지: "코드가 만료되었습니다", "이미 사용된 코드입니다", "시도가 많아 잠겼습니다. - 연결 상태 문구: 연결 화면은 사유별 한 줄을 보여 준다. 옛 토큰(401)은 "보안 방식이 바뀌어 다시 연결이 필요합니다", 폐기(4001)는 "PC에서 이 기기가 해제되었습니다", 비활동 만료는 "30일 동안 쓰지 않아 만료되었습니다", 인증 전 구간은 "연결 중". 러너가 터널을 닫기 직전 WS로 사유 코드를 보내면 "터널 닫힘, PC에서 다시 열고 QR을 다시 찍으세요", 사유 없이 끊기면 "연결 끊김, 다시 시도 중"이다.
- 터널 닫힘 예고(CEO 수용 목록의 "닫히기 5분 전에 연결된 기기에 알리고"를 대체): 자동 닫힘 조건이 "연결된 기기 없음"이라 알릴 기기가 없다. 예고는 PC 대시보드에만 띄운다. 터널 주소가 다시 열 때 바뀌는 구성(ngrok 무료)임을 `devhub-control.md`에 적는다.
- 폰에서 터널 닫기: 원격 기기에서 닫을 때 "이 기기도 끊기며 PC에서만 다시 열 수 있습니다. 실행 중 세션 N개" 확인을 받는다. 상단 터널 표시의 닫기 버튼은 한 번 눌러 펼친 뒤에만 보인다.
- 끊긴 세션: 재개하면 같은 카드에서 상태만 바뀐다. 재개 실패(작업 폴더 없음, 세션 id 무효)는 카드에 사유를 보여 준다. 저장된 마지막 200줄은 읽기 전용으로 볼 수 있다. 개별 닫기가 있고 7일 뒤 자동 정리한다.
- 같은 폴더 경고: 어느 세션과 겹치는지와 관계(같은 폴더, 상위, 하위)를 보여 주고 선택지는 "기존 세션 열기", "그래도 시작", "취소" 셋이다. 관제 AI가 세션을 만들 때 겹치면 AI가 만들지 않고 사람에게 확인 카드를 올린다.
- "보기와 승인" 기기의 화면: 새 작업, 임의 입력, 종료는 숨기지 않고 비활성으로 두고 "이 기기는 보기와 승인 권한입니다" 한 줄을 붙인다. 관제 AI 대화 입력도 비활성이다(대화가 세션을 만들 수 있으므로).
- 빈 상태와 데모: 세션이 0개인 첫 실행은 "아직 세션이 없습니다"와 다음 행동 하나("새 작업")를 보여 준다. `npm run demo`의 가짜 세션은 작업 중, 구조화된 승인 카드가 뜬 입력 대기, 오류, 끊긴 세션 네 개이고 터널 표시도 켠다(CEO 수용 목록의 "가짜 세션 3개"를 대체). 화면에 "데모" 표시를 상시 둔다.
- 접근성과 반응형: 폰의 승인, 거부 버튼은 높이 44px 이상. 위험과 일반의 구분은 색과 문구 둘 다로 한다. 승인 카드는 키보드로 포커스 이동이 되고 Enter는 승인(위험 카드는 확인 단계로), Esc는 닫기. 답 대기열은 `aria-live="polite"`. 360px 폭에서 카드의 명령 줄은 가로 스크롤이 아니라 줄바꿈.
- hook 확인 스파이크와 무인 폰 시험의 확인 항목에 추가: hook 자체 시한의 최대값, 알림을 보고 앱을 열어 승인하기까지 실제 걸린 시간, 설치된 PWA와 앱에서 페어링이 끝나는지.

- 인증 전환은 한 번에: 터널 포트에서 관리자 토큰을 거부하는 변경은 기기 토큰과 페어링이 동작하는 같은 릴리스에서만 켠다. 그 전 단계에서는 원격 접속 방식을 바꾸지 않는다. 호환 표(러너 버전, 웹, 안드로이드 APK, devhubctl, `devhub-runner` 스킬)와 "올린 뒤 할 일"(QR 다시 스캔, 새 APK 설치, devhubctl은 로컬 전용)을 `docs/runbook.md`와 CHANGELOG에 적는다. 전환 한 릴리스 전부터 대시보드에 "다음 버전에서 다시 연결이 필요합니다"를 띄운다.
- 프로토콜 버전: `hello`에 정수 `protocol`을 넣는다. 러너는 낮은 버전을 "앱 업데이트 필요" 사유 코드로 닫고, 높은 버전은 "러너 업데이트 필요"로 닫는다. 공용 픽스처에 버전 불일치 사례를 넣는다.
- 오류 규약: 러너의 HTTP 오류 본문은 기존 `error` 문자열을 유지하고 필드를 추가한다: `code`(영어 고정 식별자), `fix`(고칠 방법 한 줄), `retry`(`no`, `after_ms`, `after_fix`), 필요하면 `retryAfterMs`, 예기치 못한 실패에는 `traceId`. 예기치 못한 실패는 400이 아니라 500이고 원문 메시지는 마스킹해 로그에만 남긴다. WS 오류 메시지도 같은 필드를 가진다. 사람용 한국어 문구는 `labels.ts`에서 `code`로 변환한다. 코드 목록과 고칠 방법은 `docs/errors.md`에 코드별 앵커로 둔다. 확인: 코드 목록의 모든 코드가 문서에 있는지 검사하는 테스트.
- 새 오류의 코드: 인증은 `token_legacy`, `admin_on_tunnel`, `device_expired`, `device_revoked`, `locked_out`. 페어링은 `pair_expired`, `pair_used`. 권한은 `scope_denied`(fix: PC에서 이 기기 권한 변경). 검증은 `invalid_message`(필드 경로와 기대 타입 포함, 받은 본문은 마스킹해 로그에). hook은 `hook_unknown_session`, `hook_bad_secret`, `hook_duplicate`(같은 요청 id는 한 번만 처리). 저장은 `store_write_failed`. 터널은 `tunnel_port_in_use`. 재개는 `resume_no_cwd`(fix: 같은 지시로 새 세션), `resume_bad_id`(fix: 마지막 200줄을 붙여 새 세션).
- WS 닫힘 코드(디자인 수용 목록의 "폐기(4001)"를 대체): 4001 인증 실패(지금 뜻 유지), 4003 기기 폐기, 4004 비활동 만료, 4005 터널 닫힘, 4006 프로토콜 버전 불일치, 4029 잠금(지금 뜻 유지). 상태 표에 넣는다.
- 저장 실패는 조용히 넘기지 않는다: 교체가 3회 실패하면 호출자에게 오류를 올린다. 기기 폐기와 권한 변경은 저장에 실패하면 실패로 응답하고 메모리 상태도 바꾸지 않는다. 판단 기록 쓰기 실패는 이벤트 로그에 파일 경로와 OS 오류 코드를 남기고 관제 화면에 한 번 보여 준다.
- hook 스크립트의 실패 규약: 러너가 응답하지 않거나 시한이 지나면 종료 코드 0과 빈 출력으로 끝난다(결정 없음). 원인은 `runner/.data/hook-errors.log`에 한 줄 남긴다. 비밀값은 어디에도 출력하지 않는다. 세션별 hook 비밀값은 기존 마스킹 함수에 등록해 터미널 꼬리, 저장되는 마지막 200줄, 판단 엔진 프롬프트에서 가린다. `/runner/hooks`로 들어온 신호만으로는 승인 결정을 바꿀 수 없다(결정은 인증된 기기의 응답으로만). 스파이크 확인 항목에 hook 종료 코드와 stderr의 해석을 추가한다.
- hook 끄기: 세션 생성 옵션과 환경 변수(`RUNNER_HOOKS=0`)로 hook 주입을 끌 수 있고, 끄면 출력 꼬리 판정으로 돌아가며 배지는 "추정"이다.
- 세션 종류의 표현: 프리셋 이름으로 Claude 대화형 세션을 추정하지 않는다. 세션 메타에 `agent`(`claude`, `codex`, `shell`, `custom`)와 `interactive`(참, 거짓)를 명시한다. `dclaude`와 `devhubctl claude`(지금은 `preset: "custom"`으로 만든다, `runner/bin/devhubctl.mjs:160`)도 `agent: claude`로 표시해 hook과 재개 대상이 된다. 사용자가 직접 `--settings`를 넘긴 경우는 hook을 주입하지 않고 "추정"으로 둔다. 스파이크에서 `dclaude` 경로를 직접 확인한다.
- 승인 재전송: 요청 id별로 첫 답만 쓴다. 같은 기기가 같은 답을 다시 보내면 성공으로 돌려준다("이미 처리됨"은 다른 기기나 다른 답일 때만).
- devhubctl: `--help`와 하위 명령별 사용법을 전용 처리한다. `--json`이면 stdout에는 JSON만, 진행 문구는 stderr. 실패는 0이 아닌 종료 코드(`tunnel start`의 오류와 시간 초과 포함). 기다리는 명령(`review --wait`, `tunnel start`)에 `--timeout`을 두고 기본값을 문서에 적는다. 오류는 stderr에 `code`와 `fix`를 포함해 출력한다. devhubctl은 로컬 전용이고 원격 주소가 주어지면 요청 전에 거절한다. `devhub-runner` 스킬 문서를 같은 커밋에서 고친다.
- 러너 시작 로그(취향 결정): 로그에는 대시보드 주소만 찍고 관리자 토큰이 든 링크는 찍지 않는다. `devhubctl open`이 토큰이 든 로컬 주소를 브라우저로 연다. 이유: 러너를 DevHub 세션 안에서 띄우면 로그의 토큰이 터미널 꼬리로 폰에 전달된다.
- 데모(디자인 수용 목록의 데모 항목에 추가): `npm run demo`는 가짜 SessionManager로 node-pty를 import하지 않고, 루프백 전용, 토큰 없이 뜬다. 시작 로그 마지막 줄에 주소 하나를 찍고 브라우저를 연다. 포트가 쓰이고 있으면 다음 포트를 쓴다. Ctrl+C로 끝난다. 1차에서는 가짜 승인 카드와 가짜 끊긴 세션을 화면 모양으로만 보여 주고 2차에서 실물과 연결한다. 실패하면 원인과 고칠 방법(예: Node 버전)을 한 줄로 낸다. 확인: CI에서 데모를 띄워 `/control`이 200을 주는지 본다.

- 잠금 키: 기본 리스너에서는 X-Forwarded-For를 무시하고 소켓 주소만 쓴다. 터널 리스너에서는 터널 사업자가 붙인 값(X-Forwarded-For의 마지막 항목, cloudflared는 `CF-Connecting-IP`)만 쓴다. 페어링 교환에는 클라이언트와 무관한 한도를 둔다: 유효한 코드가 있는 동안 실패가 누적 10회면 그 코드를 폐기한다. 유효한 코드가 없으면 교환 경로는 바로 거절한다. 같은 코드의 동시 교환은 한 번만 성공한다. 확인: 헤더를 바꿔 가며 시도해도 코드가 폐기되는지, 동시 교환 테스트.
- 인증 한 겹: `authenticate(req, listener)`가 `Principal{kind: admin|device, scope, deviceId}`를 돌려주는 함수 하나로 인증을 모은다. 모든 HTTP 경로와 WS 메시지 종류에 필요한 권한(`public`, `approve`, `full`, `admin`)을 선언한 표를 두고, 선언이 없으면 거부한다. `approve` 권한이 할 수 있는 것은 세션 보기, 러너가 보관한 승인 요청과 선택지에 대한 응답, 알림 수신, 터널 닫기뿐이다. 컴파일 실행, 관제 AI, 정책과 목표 변경, 교차검증 시작, 요약 호출, 제품과 난제 쓰기, 폴더 탐색은 `full` 이상이다. `approve` 기기의 빠른 입력은 임의 문자열이 아니라 러너가 그 요청에 대해 보관한 선택지 중 하나만 받는다. 확인: 경로와 메시지 종류를 전수 열거해 `approve` 토큰으로 호출하고 표와 대조하는 테스트, 선언 없는 경로가 추가되면 실패하는 테스트.
- 단일 결정 경로: 세션마다 승인과 입력 대기를 요청 id와 revision으로 관리하는 대기열 하나(`runner/src/decisions.ts`)를 둔다. hook 신호, 출력 판정, AI 판단, 사람 응답, 관제 AI의 입력이 모두 이 경로로 들어오고, PTY에 입력을 쓰는 곳은 여기 한 곳이다. 어떤 입력이든 들어가면 그 세션의 revision이 오르고, 낮은 revision을 들고 온 답(늦게 돌아온 AI 판단 포함)은 거절한다. CEO 수용 목록의 "hook 신호 뒤 10초 안의 정규식 판정은 무시"는 이 규칙으로 대체한다. 확인: 늦은 AI 판단 거절, 한 세션의 동시 요청 두 건, 두 기기 동시 응답 테스트.
- 결정 전달 상태: 승인 요청은 대기, 결정됨, hook에 전달됨, 전달 불명, 시한 지남(터미널로 넘어감) 다섯 상태를 가진다. hook 연결이 끊기면 전달 불명으로 두고 카드에 "반영 여부를 확인하세요"와 세션 열기를 보인다. 같은 요청 id의 재시도는 같은 결정을 돌려준다. 러너가 승인 대기 중 재시작하면 hook은 결정 없음으로 끝나고 재시작한 러너는 그 요청을 남기지 않는다.
- 시한 뒤 키 전송의 안전장치(디자인 수용 목록의 "시한 뒤의 카드"에 추가): 키 전송 버튼은 카드가 터미널로 넘어간 시점의 마지막 프롬프트 줄 해시에 묶는다. 전송 직전에 해시가 다르면 거절하고 "화면이 바뀌었습니다"를 보인다. 위험 카드는 시한 뒤 키 전송을 주지 않고 "세션 열기"만 준다. hook에 `PostToolUse`와 `UserPromptSubmit`도 등록해 PC에서 답한 것을 바로 알아 대기를 해제한다.
- 자율 허용 목록(CEO 수용 목록의 허용 목록 정의를 대체): 명령은 접두어가 아니라 토큰으로 나눈 뒤 전체 일치로 판정하고, 셸 메타문자(`&&`, `;`, `|`, 줄바꿈, `$(`, 백틱, 리다이렉션)가 있으면 사람에게 올린다. 파일 편집은 실제 경로(realpath, 소문자 정규화)로 판정하고 거부 경로를 둔다: `.git/**`, `.claude/**`, `.github/**`, `**/.env*`, `package.json`, 러너 폴더 전체(`runner/.data`, `.runner-token`, 세션별 hook 설정). "읽기 전용 도구"는 이름을 열거한 목록이고 모르는 도구(MCP, 하위 에이전트, 웹 요청)는 사람에게 올린다. 기본 허용 명령 목록은 비어 있다(테스트 실행도 기본으로는 사람 확인. 작업 폴더 편집과 함께 허용하면 스크립트를 고쳐 실행할 수 있기 때문이다). `devhub-control.md`에 "허용 목록은 편의 장치이고 격리 경계가 아니다"를 적는다. 확인: 연결 명령, 경로 탈출, 정션, 러너 폴더 편집, 모르는 도구 픽스처 테스트.
- 판단 기록의 입력 저장(CEO 수용 목록의 판단 기록에 추가): 판단 시점의 입력(마스킹한 꼬리, 목표, 정책, 신호 출처, 엔진 종류와 버전, 프롬프트 해시)을 같이 저장한다. `eval:supervisor`는 두 모드다: 기록 집계와 재실행(휴리스틱은 항상, 모델 엔진은 `--engine`과 `--limit`을 줄 때만). CI는 집계와 휴리스틱 재실행만 돌린다. 판단 기록은 회전으로 지우지 않는다(이벤트만 `.1` 하나 보존, CEO 수용 목록의 보존 규칙을 이 부분만 대체). "직접 입력"은 200자로 자르고, 직전 프롬프트가 비밀 요청 패턴이면 저장하지 않는다.
- 세션별 변경 분리(CEO 수용 목록의 "세션 종료 시점 diff 사본"을 대체): 세션 시작 시 작업 폴더 경로 한정으로 기준 스냅샷을 잡는다(임시 인덱스로 트리를 만들고 미추적 파일 포함). 종료 시 같은 방식의 트리와 비교한 결과를 교차검증 입력으로 저장한다. git 저장소가 아니거나 스냅샷이 실패하면 교차검증 입력에 "기준 없음"을 표시한다. 확인: 사전 변경이 있는 저장소, 미추적 새 파일, 겹치는 두 세션 테스트.
- 연결 생존 확인: 서버가 20초마다 ping을 보내고 2회 무응답이면 연결을 끊는다. "연결됨"은 최근 pong 기준이다(hook 대기 여부와 터널 자동 닫힘이 이 정의를 쓴다). 인증 전 연결은 `hello`를 5초 안에 보내지 않으면 끊고, 인증 전 동시 연결은 20개, 인증 전 메시지는 1KB로 제한한다. 터널 자동 닫힘에 절대 상한(기본 24시간, `RUNNER_TUNNEL_MAX_HOURS`, 0은 없음)을 둔다. 터널 상태 변경은 세대 번호로 검증해 옛 프로세스의 콜백이 새 상태를 덮지 못하게 한다. 확인: pong 없는 클라이언트, hello 없는 소켓, 재시작 직후의 옛 콜백 테스트.
- 역압: 클라이언트별로 보내지 못한 양이 4MB를 넘으면 터미널 출력은 버리고 "출력 건너뜀"을 보낸 뒤 꼬리를 다시 맞춘다. 승인과 상태 메시지는 버리지 않는다.
- 기기 저장: 기기 목록은 writer 하나가 순서대로 쓰고, 고유한 임시 파일에 쓴 뒤 fsync하고 교체한다(재시도 간격 50, 200, 800ms). 응답은 저장이 끝난 뒤에 보낸다. 시작 시 파일이 깨져 있으면 기기 인증을 모두 거부하고 PC 대시보드에 "기기 목록 손상, 다시 페어링"을 띄운다. 마지막 접속 시각은 5분에 한 번만 저장한다.
- 저장 모듈 보완: 덧붙일 때 크기를 보고 회전한다(시작 시점만이 아니라). 러너는 데이터 폴더에 잠금 파일을 두어 두 프로세스가 같은 폴더를 쓰지 못하게 한다. 데모는 디스크에 쓰지 않는다. "마지막 200줄"은 5초 디바운스로 저장하고 정상 종료 시 한 번 더 쓴다. 시작 시 남은 임시 파일을 정리한다.
- 세션 환경 변수: 세션에는 `RUNNER_TOKEN`과 관리자 토큰 관련 변수를 넘기지 않는다. hook 비밀값용으로 정확 문자열 마스킹 목록을 새로 두고(패턴 기반 `redactSecrets`와 별도) ANSI 제거 뒤, 줄 분할 전에 적용한다.
- Claude 세션 id: `SessionStart` hook을 등록해 시작 직후 id를 받고 hook이 올 때마다 최신 id로 덮어쓴다. 승인 요청 id는 페이로드에 고유 id가 없으면 hook 스크립트가 호출마다 만든다. 스파이크 확인 항목에 추가: 재개 뒤 id가 바뀌는지, `PermissionRequest`에 요청별 id가 있는지, 시한 초과로 강제 종료된 hook이 어떻게 해석되는지, 이미 허용된 도구 호출도 hook으로 보이는지, Windows에서 hook 스크립트 실행(공백과 한글 경로, UTF-8 페이로드). 카드 시한은 hook 자체 시한에서 10초를 뺀 값이다.
- 재개의 중복 실행 방지: 재개 전에 이전 세션의 프로세스가 살아 있는지 pid로 확인하고 살아 있으면 재개를 막고 "이전 프로세스가 아직 실행 중"과 종료 버튼을 보인다. 재개는 세션당 한 번에 하나만 진행한다. 재개된 세션은 새 hook 비밀값을 받는다.
- 인증 전환의 되돌리는 길: 전환 릴리스 한 번 동안 `RUNNER_AUTH_LEGACY=1`로 옛 방식(터널에서 관리자 토큰)을 되살릴 수 있다(기본 꺼짐, 켜면 상단에 경고). `docs/runbook.md`에 "PC 앞에서 브라우저, PWA, 앱 세 경로의 재페어링을 확인하기 전에는 자리를 뜨지 않는다"를 적는다. 다음 릴리스에서 이 스위치를 지운다.
- 낡은 클라이언트: 웹은 4006(프로토콜 불일치)을 받으면 서비스 워커를 갱신하고 한 번 강제로 새로 읽는다. 인증 전환 릴리스의 APK는 모르는 4xxx 닫힘 코드에 재연결을 멈추고 "앱 업데이트 필요"를 보인다. 인바운드 검증은 모르는 필드는 통과시키고 모르는 메시지 종류만 `invalid_message`로 거절한다.
- 같은 폴더 판정: 경로를 realpath와 소문자로 정규화해 비교한다. 작업 폴더 상한(`D:\Projects`) 자체에서 띄운 세션은 "상위" 경고 대신 "작업 폴더 전체에서 실행 중인 세션이 있습니다" 한 줄로 따로 다룬다. 동시 생성 두 건은 생성 경로에서 순서대로 처리한다.
- 폴더 이동 커밋의 안전장치: 옛 경로 삭제와 새 경로 추가를 경로를 명시해서만 스테이징한다(같은 저장소의 다른 프로젝트 변경이 섞이지 않게). 커밋 전에 스테이징 목록에 `*.keystore`, `*.jks`, `*.apk`, `google-services.json`, 5MB 넘는 파일이 없는지 확인한다. 어느 브랜치에 커밋할지는 사용자가 정한다(지금 브랜치 `feat/painpointer`는 미푸시).
- CI의 전제: CI는 푸시해야 돈다(푸시는 사용자 승인). 경로 필터와 동시 실행 취소를 둔다. 외부 CLI(`claude`, `ngrok`, `gcc`, `python`)가 필요한 테스트는 없으면 건너뛰는 표지를 둔다. 데모 기동 확인은 별도 잡이다. `caps runaway output`을 격리로 처리하면 격리 만료일을 적는다. 프로토콜 패키지 전까지 두 사본 파일이 같은지 비교하는 검사를 CI에 둔다.
- 로컬 포트 보호: 기본 리스너는 Host 헤더가 `localhost` 또는 `127.0.0.1`인 요청만 받는다. 인증 없는 POST 경로(페어링 교환, hook 수신)는 `content-type: application/json`을 요구한다.
- 알림의 내용: 승인 알림 본문은 마스킹하고 120자로 자르며, 안드로이드 알림은 잠금 화면에서 내용을 숨긴다.
- 데모와 관문의 순서(DX 수용 목록의 데모 항목을 보완): 공식 기능 관문 결과가 나오기 전까지 데모와 README 스크린샷에는 승인 카드를 넣지 않는다. 관문을 통과하면 2차에서 넣는다.
- 주입 가능한 시계: 페어링 2분, 비활동 30일, 자동 닫힘, 카드 시한, ping 간격은 모두 시계를 주입받아 테스트한다(`AuthLockout`의 `now` 인자와 같은 방식).
- 한계의 기록: `devhub-control.md`에 적는다. 세션 안의 에이전트는 자기 hook 비밀값을 읽을 수 있어 hook 신호를 위조할 수 있다(결정은 못 바꾸지만 카드를 닫거나 지표를 흐릴 수 있다). 자동 닫힘은 기기가 붙어 있는 동안은 발동하지 않는다. 러너는 격리 환경이 아니다.
