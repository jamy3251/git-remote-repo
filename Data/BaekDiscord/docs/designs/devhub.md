## Problem Statement

개발 활동 데이터(커밋·PR·에디터 작업시간)는 GitHub와 에디터에 이미 있는데, 팀원과 친구는 그걸 못 본다. 그래서 사람들이 디스코드에 손으로 "오늘 뭐 했다" 인증글을 올리고, 팀 프로젝트 팀장은 누가 뭘 했는지 몰라 싸운다. 기존 협업툴(슬랙·노션)은 사람이 직접 써야 하고, 기존 개발자 생산성 대시보드(LinearB류)는 관리자가 개발자를 재는 도구라 개발자가 싫어한다.

만들 것: 스팀 프로필처럼 **본인이 친구에게 공개하는 개발자 프로필** + GitHub에서 자동 수집해 팀 디스코드 채널에 매일 들어가는 **팀 다이제스트**. 두 층이 같은 활동 데이터를 소비한다.

처음 비전(백준·프로그래머스·슬랙·노션·스팀·논문/과학 이슈 커뮤니티)은 유지하되 v1이 아니라 소스 플러그인 슬롯으로 둔다.

## Demand Evidence

**검증 전 가설.** 세션에서 나온 증거는 다음이 전부다.

- 창업자 답변: "이미 수동으로 하고 있는 사람들이 있다" → "디스코드에 매일 손으로 풀이/커밋 인증글" → 첫 사용자는 "팀 프로젝트에서 누가 뭐 했는지 몰라 싸우는 팀장".
- 세 차례 요청에도 실제 이름·그룹·인원·툴·주기는 나오지 않았다. 따라서 위 문장은 주장이지 증거가 아니다.
- 시장 조사(2026-09): 팀 커밋 가시화는 포화(LinearB, Jellyfish, Swarmia, GitDailies, Typo). "친구가 뭐 코딩하는지"는 WakaTime + Discord Rich Presence + 사설 리더보드가 이미 제공. 알고리즘 쪽은 BaekjoonHub, solved.ac 스트릭, 백준 디스코드 추천봇 존재. 개발자 생산성 대시보드의 반복 실패 원인은 "관리자용 측정 + 활동 지표 게임화(굿하트) + 신뢰 상실".

## Status Quo

가설: 팀원이 GitHub 커밋 후 디스코드 채널에 스크린샷/한 줄 인증글을 손으로 올린다. 귀찮아서 안 올리는 사람이 생기고, 팀장은 GitHub를 직접 뒤지거나 물어본다. 비용(시간·누락 비율)은 미측정. **The Assignment에서 실제 팀 하나로 측정한다.**

## Target User & Narrowest Wedge

- **첫 사용자(가설)**: 3~6명 규모 학생/사이드 팀 프로젝트의 팀장. 고통은 "누가 뭐 했는지 안 보인다". 이름 미확인.
- **두 번째 사용자**: 그 팀의 팀원. 고통은 "매일 손으로 인증글 올리기"와 "올려도 아무도 안 본다".
- **가장 좁은 웨지**: GitHub App(읽기 전용) → 매일 21:00 팀 디스코드 채널에 다이제스트. 팀원은 발행 후 60분 안에 본인 행의 항목 제외·"막힘" 메모·"이번엔 발행 안 함" 가능. 점수·등수 없음. 새 앱 설치 없음. 팀장이 매일 보는 화면은 **디스코드 메시지**이고 웹은 편집 전용이다. 이것이 접근 B의 마일스톤 M1이다.

## Constraints

- 1인 개발, Claude Code 활용. 기존 스택 경험: Next.js(Suyo·CaCaoTalk), Vercel 배포(LocalEye), Discord 연동(MyAgent·Listen Together), Flutter.
- 폴더명 `BaekDiscord`는 백준 우선 프레이밍이라 v1 초점(팀 가시성)과 어긋남. 이름은 미정(Open Questions).
- 프라이버시: **기본은 private.** 팀에는 다이제스트 참여(팀 리포에 커밋한 사실)로만 노출되고, 프로필·친구 공개는 본인이 소스별로 켠다(opt-in). 에디터 작업시간은 **팀 뷰와 다이제스트에 절대 노출하지 않는다**(본인·친구 뷰 전용).
- Vercel Hobby 플랜 cron 제약(프로젝트당 2개, 일 1회, 실행 시각이 시간 단위로 부정확). M1은 cron 1개로 설계한다.

## Premises (확정)

1. 첫 사용자는 팀 프로젝트 팀장. v1 데이터 원천은 GitHub 커밋/PR + 에디터 작업시간(개인 뷰 전용). 백준은 v1.1.
2. 논문·과학 이슈·코딩 문제 커뮤니티, 슬랙·노션 대체는 v1 제외, 소스 플러그인 슬롯으로만 남김. 팀장이 매일 보는 것은 디스코드 다이제스트 메시지 하나.
3. 기존 협업툴의 진짜 문제는 데이터 부재가 아니라 "데이터가 이미 있는데 사람이 손으로 옮긴다". 자동 수집이 본질, 수동 입력은 보조.
4. **(Codex 반박 반영해 수정)** 관리자용 측정 대시보드는 실패한다. 우리는 두 층으로 간다. (a) 개인 프로필 = 자발·공개·자랑용(스팀). (b) 팀 다이제스트 = 자동 수집, 점수 없음, 발행 후 60분간 본인 행만 편집(lead 예외 없음), "발행 안 함"·"기록 없음"·"미가입"·"이메일 미연결"을 구분. 감시 느낌을 막는 선은 **점수화·스트릭·비교 금지**, **작업시간 팀 노출 금지**, **편집권**.
5. 최대 리스크는 기술이 아니라 "실명 첫 사용자 부재". 이 문서는 검증 전 가설이다.

## Cross-Model Perspective (Codex, cold read)

- **Steelman**: 팀원이 디스코드에 손으로 쓰던 일일 업데이트를 개발 활동에서 자동 생성하는 도구. 개발자가 공개 범위를 통제하고, 팀장은 무엇이 바뀌었고 무엇이 막혔는지 링크와 함께 본다.
- **가장 드러나는 답**: "누가 뭐 했는지 몰라 싸우는 팀장". 이는 알고리즘 연습이나 개발자 정체성이 아니라 **조율과 신뢰** 문제다. 팀장의 싸움이 "업데이트 부재" 때문인지 "무엇이 기여인지에 대한 불일치" 때문인지 확인하라. 후자는 커밋·시간으로 못 푼다.
- **틀린 전제**: #4(프로필만으로 팀장 문제 해결). 자발적 프로필은 팀장이 걱정하는 "빠진 작업"을 감추고, 공개를 압박하면 감시가 된다. → 세션에서 두 층으로 수정 채택.
- **48시간 프로토타입**: Next.js + Supabase + 스케줄 잡 + 읽기 전용 GitHub App + Discord 웹훅. 커밋/PR/이슈를 기여자별로 묶어 미리보기→제외→"막힘" 메모→발행. 팀장 뷰는 점수 없는 일일 다이제스트. 에디터 추적·프로필·랭킹·백준·논문·피드·채팅·AI 요약은 생략. **코딩 전에 실명 팀 하나를 확보하고**, 기존 수동 게시가 다이제스트로 대체되는지 비교.
- **Codex 추천**: 실명 팀 하나 확보 + 그 팀의 디스코드 다이제스트 프로토타입. 프로필 수요는 미검증.

## Approaches Considered

### Approach A: 디스코드 안에서 끝내기 (최소) — 추천했으나 미채택
GitHub App → 디스코드 다이제스트 + `/me` 프로필 카드. 웹앱 없음. Effort S (human ~2주 / CC ~1일). 거부 이유(창업자): 스팀 프로필 비전과 확장 슬롯을 처음부터 아키텍처에 두고 싶음. **A의 내용은 B의 M1로 흡수** (단, M1은 웹 편집 페이지·OAuth·팀 온보딩이 붙어 A보다 공수가 크다).

### Approach B: 프로필 웹앱 + 팀 스페이스 (채택)
아래 Recommended Approach.

### Approach C: 데스크톱 프레즌스 클라이언트 — 미채택
Tauri 트레이 앱이 로컬 git·에디터 활동을 친구 목록에 "지금 X 코딩 중"으로 보여줌. 거부 이유: WakaTime + Discord Rich Presence가 거의 동일 기능을 이미 제공하고, 데스크톱 배포 부담이 크며, 팀장 문제(누가 안 했나)에 약함. 프레즌스 기능 자체는 B의 에디터 하트비트로 흡수.

## Recommended Approach: B — 프로필 웹앱 + 팀 스페이스

### 화면 (와이어프레임: `~/.gstack/projects/jamy3251-git-remote-repo/designs/mockup-20260922-devhub/sketch.png`)
- **왼쪽**: 정체성(아바타·핸들), "지금: {repo} · {n}분째" 프레즌스, 연결된 소스 배지(GitHub, 에디터, + 백준 슬롯), 공개 범위(소스 × 대상: 커밋→친구, 작업시간→친구, 프로필 URL→전체). 기본 전부 꺼짐.
- **가운데**: 이번 주 KPI(커밋·코딩 시간·PR 머지; 본인·친구 뷰 전용, 등수·스트릭 없음), 12주 히트맵(본인·친구 뷰 전용), 최근 활동 타임라인(자동 수집, 항목별 숨김). 활동 없는 날은 빈 줄. "안 했다"는 문구 금지.
- **오른쪽**: 친구 목록(첫 줄이 "지금 뭐 하는지"), 팀 다이제스트 카드(멤버별 커밋/PR, "막힘" 메모, "발행 안 함" / "기록 없음" / "미확인 기여자" 구분, 미리보기 → 디스코드로 발행).
- M1에서는 **오른쪽 팀 다이제스트 편집 페이지만** 만든다. 나머지는 M2~M3.

### 다이제스트 메시지 (M1 정의)
- **"오늘" 경계**: 전날 21:00 ~ 당일 21:00 KST, **웹훅 수신 시각 기준**(author date 아님).
- 디스코드 임베드 1개(제목 + 멤버당 필드 1개, 필드 25개·총 6000자 제한 안에서 리포명·커밋 수·PR 링크·커밋 제목 최대 3줄, 초과 시 "+n"). 커밋 제목 노출 여부는 팀 설정(비공개 리포 기본 off).
- 예시:
  ```
  📋 캡스톤팀 · 9/22 (월) 다이제스트          발행 후 60분 안에 편집 → https://…/d/abc
  minsu   runclue-app · 커밋 4 · PR #31 머지
          feat: 지도 클러스터링 / fix: 마커 겹침 / +1
  jamy    runclue-app · 커밋 2
          fix: 로그인 리다이렉트
          ⛔ 막힘: 카카오 로그인 키 승인 대기
  yuna    (발행 안 함)
  dohyun  (기록 없음)
  미가입: @seojin 2 commits · 이메일 미연결: 3 commits
  ```
- 위 예시는 **렌더링 근사**다. 실제는 임베드 1개, 멤버당 필드 1개(필드 value 1024자, 초과 시 커밋 제목을 줄이고 "+n"), 필드 25개 초과 팀은 M1 대상이 아니다.
- 발행 흐름(cron 1개): 21:00 cron **한 번의 실행 안에서** ① `collect(since)` 백필 → ② 초안 생성 → ③ 즉시 웹훅 발행 + 채널에 편집 링크. 별도 백필 스케줄은 없다. 편집 창은 `published_at + 60분`까지이며 요청 시 파생 계산한다(잠금 프로세스·`locked_at` 컬럼 없음). 창 안에서 팀원이 편집하면 웹훅 메시지 토큰으로 **PATCH**해 같은 메시지를 갱신한다.
- **편집 권한**: 본인 행(`digest_members`, 자기 `digest_items`)만 편집. lead 예외 없음. lead가 타인 행을 빼면 검열이고 그게 감시다.
- 전원 "기록 없음"이면 발행하지 않고 `digests.status = skipped`. 주말 포함 매일 실행하되 스킵 규칙 동일.
- **실패 처리**: 웹훅 URL 입력 시 테스트 메시지로 검증. 발행이 404/401이면 `digests.status = failed` + 팀 설정 페이지에 "웹훅 무효" 배너(실패 경로로 실패를 알리지 않는다). cron 자체가 안 돈 경우는 편집 페이지 접속 시 "어제 다이제스트 없음" 배너 + 수동 트리거 버튼으로 감지. Hobby cron 시각 흔들림이 문제가 되면 GitHub Actions `schedule`이 인증된 엔드포인트를 호출하는 외부 트리거로 대체.

### 스택
- Next.js 16 App Router + TypeScript, Vercel 배포(Fluid Compute, cron 1개 `0 12 * * *` UTC = 21:00 KST).
- Postgres: Vercel Marketplace(Neon) + Drizzle. 인증: Auth.js GitHub OAuth(M1부터, 편집 페이지 접근용). Clerk는 조직 기능이 필요해지면 검토.
- GitHub App(읽기 전용, 권한 `contents:read`, `pull_requests:read`, `metadata:read`): M1 웹훅은 `installation`, `installation_repositories`, `push`, `pull_request`만. `release`는 M3. 설치 콜백에서 "어느 팀에 붙일지" 선택 화면 → `installations` + `team_repos`. 서명(`X-Hub-Signature-256`) 검증, `X-GitHub-Delivery`로 중복 제거(`webhook_deliveries.delivery_id unique`). push 페이로드 커밋 20개 초과 시 Compare API로 나머지 수집. `dedup_key = repo + sha`. force-push로 같은 sha가 다시 오면 무시. 리베이스는 sha가 바뀌어 같은 작업이 두 번 잡힐 수 있는데, M1에서는 허용 한계로 두고 첫 팀에서 관측 후 판단. **웹훅이 정본**, `collect(since)`는 21:00 cron 실행 안의 백필 단계 전용.
- 커밋 → 사용자 매핑: push의 `commits[].author.username`(login)을 `activity_events.github_login`에 저장하고 `identities.github_login`과 매칭해 귀속. 두 가지 미확인 원인을 분리 표시한다. (a) login은 있는데 가입자가 없음 → "미가입: @login", (b) login 자체가 없음(git 이메일이 GitHub 계정과 연결되지 않음) → "이메일 미연결: n commits". 온보딩 체크리스트에 `git config user.email` 안내 포함(학생 팀에서 가장 흔한 빈 다이제스트 원인). login은 바뀔 수 있으므로 identities에 numeric id와 login을 모두 저장하고 OAuth 재로그인 시 login을 갱신한다.
- 에디터 작업시간(M2): WakaTime 호환 표면을 실제로 맞춘다. `POST /api/v1/users/current/heartbeats.bulk`, `POST /api/v1/users/current/heartbeats`, `GET /api/v1/users/current/statusbar/today`, Basic auth(우리가 발급한 `api_keys`). 하트비트 → 15분 갭 규칙으로 duration 계산. 기존 WakaTime 플러그인의 `api_url`만 바꿔 쓰게 한다. 자체 VS Code 확장은 v1.2(M6).
- Discord: **M1은 봇 없음.** 팀장이 채널 웹훅 URL을 만들어 붙여넣는다. 봇(슬래시 명령 `/me`, `/team`)은 M2.
- 성공 기준의 "수동 인증글 0건"은 Message Content Intent 없이 **팀장이 수동 집계**한다.

- **M1 필수 테이블**: users, identities, teams, team_members, installations, team_repos, webhook_deliveries, activity_events, digests, digest_members, digest_items. 나머지는 M2 이후.

- **보존·삭제**: activity_events 90일, presence 24시간. 팀 탈퇴 시 그 팀 다이제스트에서 즉시 제외(과거 발행 메시지는 유지). 계정 삭제 시 events·identities·api_keys 삭제, 과거 다이제스트 항목은 "탈퇴한 사용자"로 익명화. 앱 삭제(`installation.deleted`) 시 team_repos 비활성, 이벤트는 보존 기간까지.
- **소스 플러그인 인터페이스**: `collect(since)`, `renderEvent(event)`, `settingsSchema`. v1 구현: `github`, `editor`. v1.1: `solvedac`. v2: `arxiv`/`science-news`는 개인 활동이 아닌 콘텐츠 소스라 별도 `feed_items`.
