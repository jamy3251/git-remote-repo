# 앱 ↔ 분석 ↔ 논문 공진화 기록

원칙(2026-10-23, 사용자): 앱을 고치면 그게 논문의 어떤 질문을 바꾸는지, 논문에서 드러난 개선점은 앱의 어떤 변경으로 돌아오는지를 매 반복마다 적는다.
"이 연구가 어떤 문제를 풀고 결과적으로 어떤 의미를 갖는가"는 지금 확정하지 않고, 아래 **문제 정의** 절을 반복마다 다시 쓴다.

## 문제 정의 (살아 있는 절 — 바꿀 때 날짜와 함께 이전 판을 남긴다)

### v3 (2026-10-23)
움직임만으로 정서를 '맞히는' 것이 목표가 아니다. 지금까지 확인된 사실은
(1) 일상 각성은 저주파 손목 움직임 세기로 AUROC 0.62까지만 나오고, (2) 측정 빈도를 올려도, 큰 모델을 써도, 자기 응답을 30개 쌓아 섞어도
사용자 **안**의 판별은 좋아지지 않는다(S4·S6·S7). 남은 정보는 신호 쪽이 아니라 **라벨 쪽**에 있다 — 좋아/별로 1비트와 하루 몇 번의 ESM으로는
한 사람 안의 변화를 배울 수 없다. 따라서 풀 문제는 "단말이 **스스로 모은 풍부한 정답**(표정 계수·감정 격자·추정 맞음 여부)으로,
데이터를 밖으로 내보내지 않고, 그 사람 안의 변화를 읽게 되는가"이다. 의미가 있다면 그것은 정확도 수치가 아니라
'정답을 사용자에게서 싸게·자주·안전하게 얻는 구조'가 성립함을 보이는 데 있다. (다음 판에서 반박될 수 있음.)

### v2 (2026-10-09)

## 다음 반복 후보 (논문 쪽에서 되돌아온 것)
- 센서 HW FIFO 배치(노트9 가속도 3,000이벤트, 자이로 없음) → AP 수면 전력 측정 → 3.6 '전력 이점 미측정' 한계 해소.
- 모델을 assets가 아니라 files/에서 읽기 → APK 재빌드 없이 분석 결과를 폰에 밀어 넣음(진짜 '갱신되는 단말').
- K-EmoPhone ScreenEvent·ChargeEvent·AppUsage → '폰이 몸에 있는가' 접촉 신뢰도 게이팅. HR·EDA는 움직임 추정의 생리 기준.

- 하드웨어: ESP32 + IMU 손목 로거 → 손목 학습 모델의 도메인 격차 직접 해소, 고정소수점 이식으로 '칩셋' 절.
