## 1. 목적

공개 데이터(K-EmoPhone 77명)에서 "사용자 안(within-user) 정서 판별은 응답을 쌓아도 오르지 않는다"(S7)는 결과를 얻었고, 그 병목을 라벨로 보고 단말이 스스로 교사 라벨(표정 계수)을 만들어 학생 모델(로지스틱 33 파라미터)을 매시간 갱신하는 루프를 구현했다. 지금까지의 근거는 시뮬레이션(PREREG RQ2·RQ3)과 저자 1인 로그(RQ5)뿐이다. 이 현장 연구는 그 루프가 **저자 아닌 사람의 폰에서, 모델과 무관하게 뽑힌 무작위 시각 응답(팔 B)으로 평가했을 때** 출하(기본) 모델보다 사용자 안 판별을 올리는지 확인한다.

## 2. 현장에서 답할 가설 (PREREG RQ 대응)

| 번호 | 가설 | PREREG 대응 | 판정 자료 |
|---|---|---|---|
| H-F1 (1차) | 학생 활성 기간의 팔 B 응답에서, 사용자별 AUROC(각성)는 학생 모델이 출하 모델보다 높다. | RQ2 (d) vs (a) 현장판 | `affect.csv` `p_arousal`(출하) vs `p_student_a`(학생), 라벨 = 격자 탭 `a>0` |
| H-F1b | 정서가에서도 같은 방향. | RQ2 | `p_valence` vs `p_student_v`, 라벨 `v>0` |
| H-F2 | DriftGuard(14일·n≥15·−0.10/+0.05)는 4주 안에 참가자 대부분에서 전환 0~1회이며, 전환 뒤 14일 안 재전환(진동)은 드물다(참가자당 ≤1회). | RQ3 현장판 | `events.csv` `type=guard` |
| H-F3 | 응답 직전 5분 교사 라벨(smile_mean·jaw_mean 규칙)과 격자 응답의 일치율이 우연(이진 50%)보다 높고, 저자 로그(RQ5)와 같은 방향이다. | RQ5 | `affect.csv` 표정 열 + 격자 탭 |
| 탐색 | 팔 A(급변) 응답과 팔 B 응답의 AUROC 차이(선택 편향 크기). | RQ4 현장판 | `affect` 값 `src=ask_A|ask_B` |

RQ1(기본 모델 자체), RQ6(재식별), RQ7(비용)은 현장 자료로 다시 묻지 않는다. 다만 RQ6 관련으로 참가자 특징이 공개 가능한지는 `DATA_MANAGEMENT_PLAN.md` 6절에서 다룬다.

## 3. 설계

### 3.1 기본 설계: 4주, 기준선 1주 + 학생 활성 3주

| 주 | 단말 상태 | 참가자가 보는 것 | 수집 |
|---|---|---|---|
| 0 (설치일) | 동의·참가자 코드 입력·권한·앱 설치 확인 | 설치 안내 | `consent`, `log_start` 이벤트 |
| 1 (기준선) | 출하 모델만 표시. 교사 라벨 생성·학생 학습은 백그라운드로 진행하되 **학생 출력은 화면·질문 트리거에 쓰지 않고 가드 전환 잠금** `[앱 변경 필요: 기준선 모드 플래그]` | 하루 3회 팔 B 질문 + 팔 A(출하 모델 급변) 질문 | 매분 `affect.csv`(출하·학생 확률 둘 다), 격자 응답 |
| 2~4 (학생 활성) | 가드 잠금 해제. DriftGuard가 팔 B 채점으로 학생/출하를 자동 전환 | 같은 질문. 급변 팔 A는 현재 활성 모델의 추정 변화로 발화 | 같음 + `guard`, `train`, `teacher`, `student` 이벤트 |
| 4주 종료 | 연구자가 대면으로 로그 복사·체크섬·삭제 확인(DMP 3절) | 종료 설문(5분) | — |

- 1차 비교는 **2~4주 팔 B 응답**에서 출하 vs 학생. 두 확률은 같은 분 행에 함께 기록되므로(`p_arousal`, `p_student_a`), 사용자가 어떤 모델을 봤는지와 무관하게 사후 비교가 가능하다. 기준선 1주는 학생이 교사 표본(≥50 분)을 모으는 예열이자, 참가자가 알림 리듬에 적응하는 기간이다.
- 1주차 응답은 1차 분석에서 제외하고 "학생이 아직 배우기 전"의 참고치(출하 AUROC 안정성)로만 쓴다.
- 팔 B 응답에서의 `j`(맞아요/아니에요)는 **참가자가 그때 본 모델**에 대한 판정이므로, 1주(출하)와 2~4주(가드 결과 모델)의 일치율은 2차 지표로만 비교한다(R2 결정).

### 3.2 대안 설계: ABAB (주 단위 교차)

주 1·3 = 출하 표시, 주 2·4 = 학생 표시(가드 활성). 참가자 안에서 "보이는 모델"의 효과(j 일치율, 응답률)를 기간 효과와 분리할 수 있지만, 학생이 1주마다 꺼지고 켜지면 DriftGuard의 14일 창이 한 번도 채워지지 않아 H-F2를 답할 수 없다. 따라서 **기본은 3.1**, ABAB는 가드를 끄고 "체감 일치율"만 묻는 2차 연구가 생기면 쓴다.

### 3.3 질문(알림) 팔 — 코드 상수 (`AskScheduler.java`)

- 팔 B: 하루 `K=3`회, `09~23시` 안 균등 난수(기각 샘플링, B끼리 ≥30분). 서비스 시작·자정에 뽑아 `AlarmManager`로 예약, `ask_sched`로 기록. 팔 A 발화 15분 안이면 15분 미룸(`ask_delay`).
- 팔 A: 각성 추정이 마지막 질문 시점보다 `ASK_DELTA=0.25` 이상 바뀌고 30분(`ASK_MIN_GAP_MS`)이 지났을 때. B 직후 15분은 쉼.
- 하루 질문 상한: B 3회 + A(데이터 의존, 상한 없음). 파일럿(저자) 자료로 A의 하루 발화 수를 먼저 보고, 참가자 부담이 하루 6회를 넘으면 `ASK_DELTA` 상향을 검토 `[PENDING: 파일럿 A 발화율]`.
- 응답 화면: 기분 지도(Affect Grid, Russell) 1탭 = 정서가 `v`, 각성 `a`, 세기 `i`, 감정 이름 `e`, 맞아요/아니에요/모름 `j`. 응답 소요 약 5~10초.

### 3.4 측정 장치·앱

- 앱: `kr.ac.seoil.motionaffect` (INTERNET 권한 없음, 모든 데이터는 `files/life/`에 머묾). 상세 `docs/REPO_MAP.md` §7·§8.
- 센서: 가속도·자이로 약 50Hz 상시(`imu_*.csv.gz`, 1시간 회전). 1분 특징 16개 → 직전 30분 요약 32개(`affect.csv` `s_med_*`, `s_iqr_*`).
- 교사: 화면 사용 중 전면 카메라 MediaPipe 얼굴 블렌드셰이프 2fps → 분 집계(`face_rate`, `smile_mean`, `jaw_mean`). 프레임 단위 계수 52개는 `face_*.csv`. **영상·사진은 저장하지 않음**(`FaceRecorder.java`).
- 학생: 로지스틱(32 특징 표준화 + 33 파라미터), 1시간마다 교사 표본 ≥50이면 100스텝 학습(`OnDeviceTrainer`), `files/models/student_*.txt` 저장.
- 접촉 게이트: `contact = !충전 ∧ (화면 켜짐 ∨ 정지비율<0.9)`. 비접촉 분은 추정 보류, 행은 기록(`contact=0`).
- 가드: `DriftGuard` 14일 롤링, 팔 B 채점 n≥15, 학생 정확도 < 출하−0.10 → 출하 복귀, ≥ 출하+0.05 → 재적용. `events.csv` `guard` `to=ship|student;n;ship;student`.

## 4. 참가자

- 목표 인원: 20명(검정력 분석(experiments/field/power.py → results/field/power.csv; 시뮬레이터 p=0.8·d=0.5의 사용자별 AUROC 쌍대 차이 σ_d를 4주 응답 수에 맞춰 보정): 학생−기본 차이 δ=0.10을 Wilcoxon 양측 α=0.05·검정력 0.8로 검출하려면 17~18명, 가드−기본은 12~13명, δ=0.05는 46~71명. **기본값: 20명 모집(탈락 15% 가정, 분석 17명 이상)** — δ=0.10 검출 설계. 3~5명 파일럿은 δ≈0.2 이상만 검출 가능하므로 가설 검정이 아닌 운영 점검용으로 둔다.) (PREREG RQ2 시뮬레이션의 사용자별 AUROC 차이 분포와 참가자 부트스트랩 CI 폭으로 산출). 탈락 20%를 가정해 모집 인원은 목표 × 1.25.
- 모집 경로: 서일대학교 재학생·교직원 대상 게시 공고 + 지인 소개(스노우볼). 지도교수 수업 수강생을 모집할 경우 성적·평가와 무관함을 공고와 동의서에 명시하고, 모집·동의 과정에 지도교수가 직접 개입하지 않는다.

### 4.1 선정 기준
1. 만 19세 이상.
2. 본인 명의·단독 사용 Android 폰(Android 10 이상 `[PENDING: Android 11~15 호환 확인, APP_READINESS_CHECKLIST 1절]`), 전면 카메라, 여유 저장공간 ≥ 5GB.
3. 평소 폰으로 음악·영상·SNS 등 콘텐츠를 하루 1시간 이상 소비.
4. 4주 동안 하루 평균 3~6회 알림에 응답할 의사(사전 설명 후 자가 보고).
5. 한국어로 설명·동의서를 읽고 이해할 수 있음.

### 4.2 제외 기준
1. iOS 기기, 공용 기기, 업무용 관리(MDM) 기기.
2. 현재 정신건강 관련 치료·상담 중이어서 하루 수 회의 기분 자가보고가 부담이 될 수 있다고 본인이 판단하는 경우(자가 보고, 사유 기록 안 함).
3. 연구 기간 중 2주 이상 폰을 바꾸거나 해외 체류 등으로 기록이 끊길 예정.
4. 연구자(PI)와 평가·지도 관계에 있어 자발성이 의심되는 경우.

### 4.3 중도 탈락 처리
- 철회 요청 시 즉시 `files/life` 삭제(앱 삭제 버튼 `[앱 변경 필요: T12]` 또는 연구자 입회 삭제)와 이미 복사한 자료의 폐기 여부 선택(동의서 7절).
- 연구 완료 전 탈락 참가자의 자료는 본인이 허용한 경우에만 분석에 포함하고, 포함 여부를 결과 보고에 적는다.

## 5. 절차

1. **설명·동의(대면 또는 화상, 15분)**: 연구 설명서·동의서 교부, 질문 응답, 서명(종이 또는 전자). 동의 사본 1부 교부.
2. **설치(대면, 20분)**: APK 설치(GitHub Releases 비공개 또는 USB 직접 전달) → 앱 첫 실행 동의 화면 → 참가자 코드(`F01`…) 입력 → 권한(카메라, 알림, 사용 정보 접근, 다른 앱 위에 표시, 정확한 알람(Android 12+)) → 배터리 최적화 제외 → 곡/앱 이름 수집 토글 선택 → `life_start`. 연구자는 `events.csv`에 `consent`, `log_start`, `ask_sched` 3건이 생겼는지 확인한다(APP_READINESS_CHECKLIST 4절).
3. **기준선 1주**: 기준선 모드. 3일째에 연구자가 문자/메신저로 "알림이 오는지, 불편은 없는지" 1회 확인(응답 강요 아님).
4. **학생 활성 전환(7일째)**: 참가자가 앱에서 토글하거나 `[앱 변경 필요: 날짜 기반 자동 전환]`. 전환 시각이 `events.csv`에 남아야 한다.
5. **2~4주**: 주 1회 확인 메시지. 참가자가 앱 중단·재설치를 하면 날짜와 사유를 기록한다(`log_stop`/`log_start`로 자동 기록, 사유만 수기).
6. **종료(대면, 20분)**: 종료 설문(알림 부담 1~5점, 질문 횟수 적정성, 표정 카메라 인식 여부, 배터리 체감, 자유 의견) → 연구자가 USB로 `files/life`, `files/models` 복사 → 체크섬 → 참가자가 원하면 즉시 단말 삭제 입회 → 보상 지급.
7. **보상**: `[PENDING: IRB 기준 금액]`(모바일 상품권, 완료 시 1회. 중도 철회 시 참여 주 수에 비례).

## 6. 측정 변수

### 6.1 1차 결과 변수
- **사용자별 AUROC(각성) 차이 = 학생 − 출하**, 2~4주 팔 B 응답에서. 라벨: 격자 탭 `a>0` 양성, `a<0` 음성, `a==0` 제외(R2). 예측: 응답 직전 분 행(`s8_common.row_before_tap`, 5분 창)의 `p_student_a` vs `p_arousal`. 사용자 포함 조건: 팔 B 응답 ≥20건 · 두 부류 모두 존재.

## 7. 중단 기준

### 7.1 참가자 단위 (해당 참가자만 종료)
- 본인 철회 요청(사유 불문).

## 10. 알려진 한계 (사전 명시)
- 출하 모델은 K-EmoPhone **손목** 8Hz 가속도로 학습됐고 현장은 폰 50Hz다. 출하 모델이 낮게 나올 수 있어 "학생 > 출하"는 개인화 효과와 도메인 보정이 섞인 결과다. 비교군으로 "씨앗 + 팔 B 선행 응답 파인튜닝"(PREREG (b))을 사후 오프라인으로 추가한다.
- 응답 ≥20건 조건은 4주 × 3회 × 응답률 60%면 약 50건이므로 달성 가능하지만, 응답률이 낮으면 참가자가 분석에서 빠진다. 응답률은 2차 변수로 보고.
- 교사는 화면을 볼 때만 작동하므로(얼굴 검출률 앱별 12~79%, S5) 폰을 내려둔 상황의 학생 성능은 `held` 분리 평가로만 본다.
